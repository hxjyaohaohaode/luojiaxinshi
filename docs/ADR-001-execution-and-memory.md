# ADR-001：记忆策略、上下文一致性与持久执行记录

状态：已在 1.5.0 采用。日期：2026-10-18。

## 问题与约束

现有 MVP 的通知、待办和确认流程已经持久化，但模型任务状态主要依赖进程；重启可能留下处理中记录，记忆的范围、有效期和冲突也不能只靠提示词约束。长期目标包含更多渠道和多阶段办理，同时必须保留当前数据、避免额外维护平台和不可控模型循环。

当前部署目标仍是单实例、个人或小规模受邀试用，SQLite 为事务边界。模型是有时延、有费用、可能超时且不能和本地数据库共同提交的外部依赖。不能以自动重试掩盖不确定的计费结果。未以合成浏览器测试推断校园规模容量。

## 决策

保持模块化单体，将确定性政策从路由和大提示词中分离。新增模块均由实际请求调用，没有独立空服务或新的运行依赖。

| 边界 | 负责的行为 | 主要调用方 |
|---|---|---|
| `memory_policy.py` | 有效期、显式互斥键、范围优先、冲突隔离、去重 | 记忆 CRUD、召回、上下文版本检查 |
| `context_snapshot.py` | 获准资料、日程、个人条件和有效记忆的指纹；生成与提交时重检 | `grounding.py`、流式与兼容接口 |
| `execution.py` | 执行所属进程、心跳、阶段、终态、失联恢复 | 应用生命周期、通知整理、聊天 |
| `model_catalog.py` | 已核验模型 ID、官方端点、凭证通道匹配和公开配置 | `Settings`、会话配置与语音入口 |
| 既有 `context_engine.py` / `harness.py` | 本地历史打包、真实调用计量、有界修复 | 证据链路 |

```mermaid
flowchart LR
    A[用户确认的输入与范围] --> B[事务保存问题和执行记录]
    B --> C[有效记忆与上下文指纹]
    C --> D[本地检索和历史打包]
    D --> E[有界模型调用与独立复核]
    E --> F[事务重检版本并提交结果与终态]
    F --> G[办理草稿或回答]
    H[进程心跳和失联恢复] --> B
```

### 记忆决策

同一个账号可明确选择跨项目通用、项目或专题记忆。`semantic_key` 表示本人声明这些条目属于同一互斥事实，系统不会推断任意自然语言矛盾。相同键按项目、专题、通用的顺序选取；最高层级存在不同内容则全部暂不召回，要求本人处理。跨专题冲突在该对话预览中显示，需要编辑或停用相应条目。

有效期采用 Unix 秒保存，前端按设备时区输入和显示。已停用、未到生效时间、已过期的条目不进入召回。内容相同但来源不同的条目不会被偷偷合并。冲突确认、版本检查、保留项与停用项在同一事务内写入。JSON 导入保留策略但统一停用，避免导入即改变个人服务。

### 一致性决策

在生成前固定用户授权范围的状态指纹，规划及写作等边界重检，并在最终数据库提交事务内再次重检。旧用户资料快照与生成初始资料不一致也会拦截。变化时保留问题和材料，提示根据最新内容重试，不在后台自动替换输入再发起收费请求。

当前账号资料库全范围授权时，指纹会包含该账号资料及通知版本；修改一份未被选中的资料也可能让回答停止。这是保守的一致性取舍，后续可在明确检索依赖后缩小失效范围。指纹保留哈希和访问类别，不额外存储可恢复的个人内容；已有证据快照仍按照应用原有账号权限保存。

### 执行与故障决策

每次执行持久记录尝试 ID、所属进程、处理令牌、阶段和终态。进程每 10 秒续期，租约 45 秒。正常关闭清理本进程工作；强制退出后，下次启动或心跳检查将过期的运行记录标为中断。时间值是配置策略，事件循环阻塞、磁盘延迟会影响实际恢复时间，不能承诺精确秒数。

旧进程、取消后的回调或旧任务恢复不能清除新尝试的令牌。旧消息仍需结束自己的处理中状态。成功结果和执行终态同事务提交；终态不可被迟到成功回调反转。任务在协程第一行之前被取消时，完成回调也必须解除订阅等待并释放并发槽。

远程模型可能已完成或已计费，但本地未收到结果。系统记录中断和重试入口，不自动重放。这里没有持久恢复模型内部思考、分布式队列、幂等计费或恰好执行一次承诺。租约能区分进程所属，不代表整体服务可多副本运行：并发限制和主动取消仍在进程内，正式部署仍用单实例。

### 模型与成本决策

模型目录按小米官方文档核验，配置支持 V2.6 Pro、Flash、Pro UltraSpeed 及对应通道限制；语音继续使用官方 V2.5 系列。默认主模型与复核保持 Pro，禁止静默降级或换供应商。普通 API 与 Token Plan 的凭证、端点和适用模型配对验证；目录表示适配支持，账号实际权限需请求验证。

历史压缩和状态提示使用本地计算，不新增摘要调用。短材料文字问答仍需一次写作和一次独立复核；其他任务按证据覆盖增加步骤。修复次数、有无进展与总时限共同限制开销。当前没有以单样本耗时设立 P95 承诺，也未声称已实现跨请求结果缓存。

## 备选方案与后果

| 方案 | 收益 | 未选原因／保留条件 |
|---|---|---|
| 直接集成 Mem0 与向量服务 | 模型抽取、语义检索、多存储支持 | 现阶段增加外部依赖和调用；待真实词项召回失误有评测证据后，引入可替换召回器，并保留当前权限和有效性过滤 |
| 整体迁移 LangGraph | 检查点和复杂工具工作流 | 迁移面较大，不能自动解决模型计费幂等；未来有真实多工具续跑需求时逐个节点接入 |
| 自动恢复后续跑收费请求 | 表面上减少操作 | 远端完成状态不明，可能重复计费和使用过时输入；当前保留本人重试 |
| 立即拆微服务／队列 | 独立扩容和调度 | 当前缺少容量证据，会增加部署与事务补偿成本；多实例前先外置并发、取消和任务队列，完成故障测试 |
| 全量重写前端框架 | 统一新组件系统 | 不能直接补齐业务状态；在现有交互和样式上修复实测问题，保留既有办理能力 |

主数据库仍为版本 4，记忆扩展由 1 升到 2，执行扩展为 1。迁移仅新增表和策略，拒绝高于支持范围的结构；升级前备份，回退应使用匹配旧程序的备份副本。验证入口与实际结果见 [TESTING.md](../TESTING.md)，采用的固定上游源码见 [OPEN_SOURCE_REVIEW.md](OPEN_SOURCE_REVIEW.md)。
