# 自主记忆与多来源维护 v5

日期：2026-10-21。应用 1.15.0，记忆引擎 schema 5。沿用 [生命周期 v3](MEMORY_LIFECYCLE_V3.md) 与 [可靠性 v4](MEMORY_RELIABILITY_V4.md)，本轮重点是减少用户配置，把形成、选取、修订和来源变化接入真实工作流程。检索/权限/写入工程测试使用隔离数据库和模拟模型；另对实际模型进行合成片段协议检查，不发送真实账号正文。验证结果见 [TESTING](../TESTING.md) 和 [机器汇总](verification/memory-autonomy-v5.json)。

## 用户实际怎样使用

新对话默认由 AI 按问题选择相关项目和专题，无须先到记忆设置逐项勾选。已有明确的手动范围继续保留；在“项目与记忆”切回自动即可解除限制。自动模式仍受账号所有权、资料权限、会话共享设置、时效、场景和用户关闭记忆的约束。

对话中的明确事实、稳定偏好和纠错，可以直接保存或更新。无需特意说“记住”，也不要求对每一条忠实整理再次点确认。“这次”“今天”“暂时”的要求保留在短期层，不覆盖跨会话偏好。推断、缺乏原话支持或明显加入新身份/数字的改写继续待核对，不把模型自报 `explicit` 当成事实证明。

记忆卡片保留手动编辑，并提供“AI 修改”。在正文中选中一段，填写要求，点击“AI 修改并保存”，服务器只替换对应的 Unicode 字符范围；不选择文字时整理整条。改写保留版本历史，保护本人修订，归档和停用状态保持原样。资料索引经本人修订后，来源变化会暂停旧索引；可点“按当前原资料重建索引”，一次操作恢复跟随来源，手工版本仍可恢复。

## 不经过对话也能形成的记忆

| 来源事件 | 自动形成与维护 | 使用边界 |
| --- | --- | --- |
| 通知原文或附件新增、解析状态/有效性/正文改变 | 形成带标题和摘录的资料索引；来源版本改变后立即排除旧索引，后台更新同一条记录 | 依然是资料索引；不是用户偏好，不能单独证明当前官方要求 |
| 对话上传资料、资料库全文新增或变化 | 优先从可用全文形成有界摘录，关联原资料和来源对话 | 关闭资料库后，只有允许使用的当前对话附件仍可用；不能把别的会话附件通过记忆带入 |
| 项目说明新增或修改 | 有正文说明的项目形成项目范围的资料索引，随说明维护 | 项目名称本身不证明用户身份或官方规则；空说明不生成无实质内容的条目 |
| 待办创建、状态及办理进度/结果/下一步改变 | 维护本人办理记录，保留“本人记录不等于学校确认办结”的限定 | 日程权限及历史经历降权继续生效；不将旧办理经历当作当前要求 |
| 用户对回答中实际使用版本给出反馈 | 更新该版本的相关性/过时状态，旧反馈不迁移成新版质量证明 | 曝光和 AI 自报采用都不是用户认可；不同版本分别评价 |

这些路径由 SQLite 触发器写入持久队列。后台约每 10 秒尝试分批处理，每批最多 24 个本地作业，同一账号正在生成回复时延后；积压时不是“10 秒内一定完成”。同一来源的连续变更合并排队，处理与回执在同一写事务提交。来源读取失败、资料不可用或模式为手动/关闭时，不伪造已经学会。

资料索引只是标题及最多约 1,100 字的摘录，没有声称对整个文件完成了语义理解。记忆用于辅助定位和理解背景，具体期限、资格和办理结论仍须使用当前原文检索证据。自动索引和本地维护不产生额外模型请求。

## 自动选择与对话维护

现有查询规划器同时选择自己账号目录中的项目 ID 和专题；不额外增加一次“选记忆”的付费调用。目录输入受条数与 5 KB 字节预算限制，本轮最多选择 3 个项目、8 个专题。没有模型规划时使用项目名/专题名和唯一相关线索进行本地路由，不能保证理解所有隐晦指代。

候选继续经过范围、权限、短期/长期层、来源和适用场景检查，再用已有词法、概念、facet、时间、反馈和 MMR 排序。多项目内容携带所属名称，去重及同类限制保留范围，避免把两个项目中相同措辞的约束合并成一个不明来源。只有相关候选进入有界上下文；自动选择不是把全部账号记忆塞给模型。

对话维护沿用 `memory_actions`，增加明确/推断依据、目录内项目选择和局部替换范围。原话必须来自本轮用户；引语、假设、第三人说法、凭证、指令注入和明显时效限制不能冒充稳定用户事实。同一轮的本地原话和 AI 忠实整理可合并，不重复生成同一偏好。明确纠错可在本次要求内修改人工保护的原子事实；多句条目必须给出局部范围，或由用户明确要求整条重写。成功应用后清除同一轮已被替代的待核对草案，历史及实际证据保留。

服务器对明显新增数字、身份/语言改变、否定翻转和低字面支持的改写做保守检查。这不是完整语义等价证明；不将确定性夹具的成功率当作真实模型的语义准确率。

## 版本、权限、遗忘和编辑可靠性

原资料版本计数与队列在同一事务递增。召回用索引和来源的当前计数比对，后台尚未更新时也排除旧记录及派生内容。检查按选中 ID 和主键索引完成，避免每次发布检查扫描全部资料或重新读取全文。办理工作流的变化同样纳入来源计数；只改结果说明、未改变任务主版本时，旧办理记忆也会暂停。

来源删除会清理关联索引及派生记录。关闭资料或日程权限时，派生概览继承限制。遗忘不仅删除当前记录，还阻止同一来源自动重建；清空全部记忆时，同时封住已经存在但尚未处理的资料/任务作业，避免后台稍后从旧事件重新学回。清空之后新加入的来源仍可正常形成记忆。

AI 修改由用户一次明确点击发起，只发送所选正文及修改要求；使用已配置的摘要模型，单次有界请求，无自动收费重试。按账号和每日模型额度计数，每小时最多 30 次。AI 编辑回执精确核对请求字段的大小写和空格。相同操作标识和相同输入重试读取原结果；处理中不重复请求；失败或超时可能已经计费，新的请求须由用户再次点击。提交时重新核对版本，处理期间发生修改或遗忘就丢弃旧结果。

本轮没有启用未授权的后台付费语义复盘，也没有把原资料发送给另一个记忆服务。原有可选语义复盘的预算、令牌、授权和质量限制继续保留。

## 上游借鉴和工程取舍

继续基于 [13 个固定快照的源码审查](MEMORY_SOURCE_REVIEW.md)，并非本轮重新逐行审读全部上游代码。EverOS 的持续组织与 MemU 的宿主 Agent 分工体现为普通业务事件/对话主动维护；MemOS 的纠错与 Graphiti 的时态来源体现为来源变化立即失效、同一记录版本化更新；Letta 的可编辑性体现为局部 AI 编辑、人工保护和可恢复历史；Mem0 的回执/遗忘原则体现为有界单次模型编辑、同意图重放，以及未处理旧来源也不能在全量遗忘后回流；ReMe/Cognee 的增量作业原则用于来源队列和重启恢复。

这些机制按现有 FastAPI、SQLite、原生前端和权限边界重写，没有引入上述项目的运行时服务或移植其源码。前端继续复用 [v4 实际核对过的组件交互](MEMORY_RELIABILITY_V4.md#5-前端的实际参考与业务适配)：卡片直接操作、低频表单项折叠、来源/历史时间线及减少运动；没有新增 React、Motion 或大型组件依赖。

## 部署与回退

schema 4 升至 5 时保留业务表、人工正文与已有手动范围。新增自动模式、消息选取快照、AI 编辑回执、资源来源绑定与版本计数。现有资料与项目说明进入本地队列；已有办理记录与工作流关联迁移后重新核对。升级前通过 SQLite backup API 创建一致性备份并校验完整性/外键，运行空闲时再重启。公开证据只保存汇总，不含账号正文、原数据库、密钥或邀请码。

schema 5 不能直接交给只认识 schema 4 的旧代码。回退须停止写入、核对升级后新增数据并恢复升级前备份；这样会失去备份之后的业务修改，不能把覆盖现有数据库当作无损回退。日常恢复优先用已有版本历史与备份操作流程。
