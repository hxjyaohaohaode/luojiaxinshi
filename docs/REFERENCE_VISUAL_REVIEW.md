# 参考实现与实际页面的视觉复核

本轮基线为 `c127c1d`。已有测试通过不能证明视觉全面或符合用户审美；本轮先看真实运行页面，再修改可复现的问题。真实账号仅用于查看页面，交互回归和公开截图使用 `8786` 上的合成数据。没有把合成数据当作真实模型质量证据。

## 反向复核

- 检查 320、390、1024、1413 像素下的长标题、工具栏分行、按钮边界和首项位置。
- 记忆检查窄侧栏/宽侧栏、空详情、打开与关闭详情、手机目录展开；不能只检查有内容的桌面截图。
- 搜索、状态筛选和看板/清单切换之后，输入继续保留。
- 来源预设打开真实编辑表单，平台预填；退出回到触发入口。
- 原有稳定性回归继续覆盖聊天来源面板的 DOM、字号、输入、阅读锚点和音频复用，以及暗色系统偏好、低高度表单、旧响应、失败重试和减少动画。
- 新增测试 `scripts/verify_visual_review.mjs` 检查可量化的边界并输出截图。`tests/memory-list-text.test.mjs` 检查中文句界、换行、无标点长文本和补充 Unicode 字符。

视觉检查中发现的两个二次问题已经修正：删除旧标签后 `.focus-label > span:last-child` 误命中状态圆点；旧的 320 像素数量整行规则挤压了列表。弹窗退出的焦点恢复发生在下一帧，测试等待实际状态后再判断，而不是更改原有恢复行为。

## 证据与验收边界

GitHub Actions 的 `synthetic-browser-reports` artifact 包含新增的 `visual-review-browser/report.json`、截图和执行日志。检查数量只表示这些已列明的场景，不能用来证明“最终版”“没有其他问题”或替代用户的视觉验收。

本轮没有更改业务记忆策略、模型生成质量或另一项任务正在实现的 Agent 执行器。聊天、日历、登录、办理表单继续走已有交互回归；新增视觉修正集中在上表已确认的问题。
