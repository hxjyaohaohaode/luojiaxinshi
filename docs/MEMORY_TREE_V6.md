# 自主记忆与知识树 v6

本轮把记忆的组织、原始资料覆盖、Agent 写入能力和使用界面一起升级。运行版本为 1.16.0，记忆引擎 schema 为 6。此前 v1–v5 文档保留为历史记录；当前行为以本文、实现及验证记录为准。

## 现在的使用方式

默认自动积累与维护。用户不必选择每轮要用的记忆，也不必在记忆审核队列中逐条确认。界面以目录、内容列表和详情区组织；详情可直接修改正文、让 AI 修改整条或选定部分、查看原始来源与版本。用户可以建立、重命名和移动目录；移动不改变项目、专题和访问边界。手动位置及手动正文受保护。

知识树包括长期记忆、经历与经验、资料与知识。长期信息按项目／专题／通用范围及内容类别组织，再容纳自定义目录。会话条件及工作记录保留独立入口，按原会话与临时有效期使用，不自动变成永久习惯。稳定信息仍需明确长期意图，或满足已有的跨会话晋升条件。

树使用持久化的父子节点、成员关系和增量脏记录。不是仅靠前端将平面列表缩进。Agent 可以读取有界的目录提示，并选择相关目录、项目和专题；检索先遵守权限、来源及生命周期，再结合目录、中文全文匹配、信息槽位、时效、来源关系与使用反馈排序。宽泛根目录不会把多个无关项目一起带入当前回答。

## 形成、更新和遗忘路径

| 输入 | 自动路径 | 保留的边界 |
|---|---|---|
| 用户对话 | 规则捕获临时条件；回答 Agent 用结构化操作建立、修订、整理长期信息或工作栏目 | 逐字原话、当时范围、消息代际；假设与引用不作为本人事实 |
| 通知原文、上传资料及完整解析正文 | 来源版本触发持久作业，全文按段落定位分片，建立独立全文索引；更改时原片段立即失效，后台更新 | 当前来源、原文位置、字符偏移、账号、资料库／当前附件权限 |
| 项目介绍 | 建立项目资料知识；Agent 可依据明确原话中的项目名称自动建立项目目录 | 不能从附件猜用户项目，不能越过手动限定范围 |
| 本人办理与工作流变化 | 延续已有任务事件路径，自动更新待办和经历 | 本人记录不等于学校办结；关闭日程权限后不调用 |
| 模型已读取的通知／资料 | `source_remember` 摘取有精确来源证明的知识，自动归类 | 必须来自该轮实际提供的原资料，不能只凭模型声称；不能成为个人偏好 |
| 用户手动编辑与导入 | 版本检查后保存，保护正文和位置；导入保留启用状态及目录 | 导入 ID 映射到当前账号，历史来源作为声明保留，不恢复外部访问权限 |

资料不再只有前 1100 字。简短入口摘要继续作为定位辅助；独立的 `memory_source_units` 与 FTS 保存全部当前可解析正文。每片最多 1400 字、相邻重叠 200 字，保留段落定位与原始偏移；回答中只装入问题相关的有界摘录。资料知识有独立存储，达到 10000 条可编辑记忆的上限时，完整资料分片仍能建立和召回。

Agent 新增 `organize` 操作及 `path` 子目录参数，可整理实际提供的条目；受保护的人工作品不被自动移动。新增 `project_name`，可以直接使用明确原话中的新项目名称，不要求用户先进入设置。`source_remember` 可以忠实摘录整句，不允许在资料之外编造事实、将资料变成用户习惯，或虚构来源位置。摘要／方法若完整保留可核验的来源片段，可自动采用；含新推断的内容仍不会直接投入使用。

来源变更后，旧知识的指纹立即不匹配，不等待后台作业就停止调用。对未被人编辑且整段依据仍在原文中的知识，自动续接新来源版本并记录修订；依据消失时保留旧历史并停止调用，当前原文分片继续提供最新依据。人编辑过的正文不会被重建索引覆盖。

没有依据的提议在后台暂缓，不形成用户待办。自动维护会重新检查可核验的原话与冲突，长期没有足够依据的提议在 30 天后归档。为了兼容旧接口，内部仍保留 `pending` 字段及旧审核 API；默认界面没有审核标签页、逐条采用／拒绝按钮和审核模式。旧的 `review` 设置会转为 `auto`，通过普通编辑建立本人明确内容仍然可用。

遗忘优先于自动学习。延续原有内容墓碑、消息片段撤回、来源阻断与代际边界；源资料知识的遗忘采用来源级阻断，防止同一资料片段或提炼结果重新出现。原始文件、原对话及离线备份保留自己的生命周期，记忆遗忘不等于删除它们。当前没有跨任意重写的语义级“同义事实遗忘”保证。

## 来源核查与技术取舍

本轮重新完整读取了现有 13 个固定版本的 24939 个文件；对压缩包重新核对 SHA-256 与 ZIP CRC，解压文件哈希与原清单一致。按本轮 `splitlines()` 统计，23875 个 UTF-8 文本文件共 6317741 行；这与旧报告的文件类型和末尾换行计数方法不同，不能把行数差当成源码变更。每个 Python 文件建立语法及符号位置索引，核心机制再针对实现函数审读。OpenViking 的一个惰性链接占位文件产生预期语法标记。摘要证据见 [固定版本复核清单](verification/memory-upstream-v6.json)，逐文件清单在工作区父目录的 `.codex-work/memory-v6/full-file-audit-v6.jsonl`。

全量文件读取、哈希和符号扫描不等于逐行人工理解 631 万行，也不等于运行了上游服务、测试或完成安全认证。未执行参考仓库的安装脚本和服务。没有用“融合百分比”代替功能证据。

本轮主要沿用 memU 的宿主 Agent 负责语义、独立来源与变更提交思想，结合 EverOS 的可恢复增量协调、LangMem 的结构化写入工具和分层上下文索引。以下列出其余逐一审读后的采用与限制，避免把未实现的向量／知识图谱系统写成已集成。

## 性能与验证边界

回答仍限制最多 12 条、约 8000 UTF-8 字节的记忆上下文。资料先做中文全文索引并按相关内容截取，权限及来源版本在截取前后检查；完整解析正文在本地存储，不会为了后台整理全部发送给模型。上下文有效性检查改用数据库触发器维护的来源版本，不在每个阶段反复序列化完整文档；任何来源正文或完整解析结果的变更仍会使旧结果失效。

所有者、目录循环、最大层级、并发版本、事务回滚、来源更改／删除、权限、遗忘、全文尾部检索、容量上限、历史回答、模型提炼与局部编辑均有工程测试。模型输出用明确夹具测试协议；这些测试不能作为外部模型真实准确率、任意资料解析率或生产延迟保证。复现命令与当前实测见 [TESTING](../TESTING.md)。
