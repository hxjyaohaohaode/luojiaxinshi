# 校园容量与事项归组契约 · 1.23

## 账号容量

容量统一由 `app/usage_limits.py` 的 `UsageLimits` 定义，并随应用数据库连接传递。手动收件、官网／公众号／群接入、对话分支、通知转会话、材料版本、个人项目及 JSON 导入使用同一部署配置，写入检查与保存位于同一事务。重复收件及幂等重试不占用新的记录名额。

| 项目 | 旧默认 | 新默认 | 配置字段 |
| --- | ---: | ---: | --- |
| 每账号通知 | 200 | 10,000 | `notices` |
| 每账号会话 | 100 | 2,000 | `conversations` |
| 每账号来源目录 | 100 | 1,000 | `sources` |
| 原件与全部本人材料版本 | 200 MB | 10 GB | `storage_bytes` |
| 每事项本人材料 | 40 | 200 | `materials_per_task` |
| 每份材料版本 | 20 | 100 | `versions_per_material` |
| 每事项提交记录 | 100 | 500 | `submissions_per_task` |
| 站点注册账号 | 5,000 | 200,000 | `registered_users` |
| 每账号项目 | 100 | 1,000 | `memory_projects` |
| 每账号个人安排 | 1,000 | 20,000 | `arrangements` |
| 每账号待办 | 部分入口 5,000 | 100,000，入口统一 | `tasks` |
| 每账号助手任务会话 | 100 | 2,000 | `agent_threads` |
| 自动整理默认每日尝试 | 10 | 200 | `automation_daily_default` |
| 自动整理可设置每日上限 | 50 | 1,000 | `automation_daily_max` |
| AI 每账号每日处理额度 | 30 | 1,000 | 独立配置 `AI_DAILY_LIMIT` |

`USAGE_LIMITS_JSON` 接受以上表中的容量字段，未填写的字段采用默认值。例如 `.env`：

```dotenv
AI_DAILY_LIMIT=1000
USAGE_LIMITS_JSON={"notices":20000,"storage_bytes":21474836480,"automation_daily_default":200,"automation_daily_max":1000}
```

配置必须是正整数；未知字段、布尔值、负数及自动整理默认额度大于最大额度均拒绝启动。修改后重启。`AI_DAILY_LIMIT` 可设 1—10,000，自动整理同时受到它约束；每则通知可能产生多个模型请求。配置没有无限额度或付费等级逻辑。

既有账号自动使用新的部署容量。已有个人自动整理设置保持本人选择，部署调低上限时按较小值执行；不会因为提高额度自动开启来源、AI 或推送。注册容量为数据库业务边界，不代表已验证 20 万用户的并发能力。

`GET /api/account/usage` 返回本人实际计数及生效上限；前端入口为“个人与账号 → 账号服务 → 账号容量”。单次文件、正文、压缩包展开、请求大小和认证防滥用边界单独保留，不与账号累计容量混用。检索已移除逐则通知查询附件与任务的 N+1 SQL；新版相同内容收件使用账号＋内容指纹索引，历史非新版指纹仍作实际内容核对。

## 同一事项

目标是把原通知、补充要求、延期及后续信息放在一起判断和办理。原通知中的事实、个人待办与个人提交记录仍各自保留。

1. 通知详情按标题的具体事项提示候选，不调用模型。显式年度、批次、学期及场次冲突不推荐；信息不足或未发现候选时可搜索其他通知。
2. “核对归组”预览展示将受影响的全部通知、来源、时间、待办、材料、期限与提交要求。两则通知已经各有归组时，预览展开双方全部成员。不同年份或来源有明确核对提示。
3. 用户可以命名事项并确认归组，也可以选择“不是同一事项”。排除只对当前原文版本生效；通知变更后允许重新出现。
4. 归组不改变原文、适用人群、截止时间、已确认待办、本人计划、文件版本或提交状态。不能因为后收一则通知就认定它覆盖原通知。期限冲突仍由原有变更核对流程处理。
5. 通知列表默认将已经确认的同一事项收拢，仍按当前行动分类及检索筛选。组卡同时给出全组数量和当前匹配数量，不把被筛除的通知重新混入结果；“按事项归组”按钮可切回逐则查看。
6. “将本通知移出事项”可撤回关系，原通知及办理记录保留。两成员组移出或删除其中一则后自动解组。

所有查询、候选和变更限定本人账号。确认令牌绑定组版本、成员通知版本及所有任务／工作流版本；预览后发生变化返回 409，要求重新核对。归组和拆组位于写事务中，防止并发编辑丢失成员。单组最多 200 则，用于防止一次误把整个资料库归为一个事项。

## 接口与持久化

| 接口 | 行为 |
| --- | --- |
| `GET /api/notices/{id}/matter` | 当前事项、候选及拆组令牌 |
| `POST /api/notices/{id}/matter/preview` | `{other_id}`，返回完整成员、核对提示及确认令牌 |
| `POST /api/notices/{id}/matter` | `{other_id,token,title}`，确认归组 |
| `DELETE /api/notices/{id}/matter` | `{token}`，将当前通知移出事项 |
| `POST /api/notices/{id}/matter/dismiss` | `{other_id,token}`，排除当前候选 |
| `GET /api/notices`、`GET /api/notices/search` | 每则通知附带 `matter` 摘要，仍保留逐则数据 |

数据库新增 `notice_matters`、`notice_matter_members`、`notice_relation_dismissals`、`import_notice_links`，元数据版本为 `notice_matters_schema_version=1`。删除账号会级联清理关系。备份校验会拒绝有版本标记却缺表的数据库。

JSON 导出携带 `notice_matters`；导入通过当前账号的原始标识映射恢复关系，幂等重试不会再归组。缺少成员或会覆盖既有归组时拒绝本次事务，并给出可恢复的错误。原有本人文件库／提交快照的 JSON 恢复限制继续保留在导入预览中；完整恢复仍用数据库备份。

## 验证边界

自动测试覆盖旧容量门槛、配置边界、跨入口统一检查、导入原子性、账号隔离、候选保守排除、合并／拆组、过期预览、组内记录不变、JSON 与数据库备份。浏览器脚本在 Chromium、Firefox、WebKit 中操作真实本机接口，包含窄屏和键盘占屏高度；数据为隔离夹具，不调用真实模型或对外发消息。

相近标题候选属于辅助核对，未声称已实现任意正文的语义识别或自动确认归组。真实公众号／群凭证和目标设备推送仍待授权后的真实联调；本次不把模拟接口验证称为真实渠道完成。
