# ADR-007：按次选择通知处理模型与保留质量门槛

日期：2026-10-18。实现版本：1.10.0。状态：采用。

## 问题与实测

Pro 提取、Flash 思考复核的复杂通知完整调用曾耗时 305.282 秒，逐份原文复核的单独重放耗时 133.219 秒。已有诊断表明，关闭思考或改用 Flash 提取会遗漏依赖、材料或误判职责，不能把缩减检查当作提速成果。

小米当前提供 `mimo-v2.6-pro-ultraspeed`，支持本应用使用的思考、流式和 JSON 输出。2026-10-18 核对的价格为：未命中缓存的输入 ¥30／百万 token、缓存输入 ¥0.25／百万 token、输出 ¥60／百万 token；常规 Pro 对应为 ¥3／¥0.025／¥6。普通输入与输出单价是 Pro 的 10 倍，不能直接等同于整个双模型工作流的费用倍数。依据：[UltraSpeed](https://mimo.mi.com/models/en-US/mimo-v2.6-pro-ultraspeed)、[Pro](https://mimo.mi.com/models/en-US/mimo-v2.6-pro)、[Flash](https://mimo.mi.com/models/en-US/mimo-v2.6-flash)。实际费用以平台账单为准。

## 路由与授权

- 全局默认模型保持原配置。维护者设置 `NOTICE_FAST_ENABLED=true` 后，普通按量通道的通知页显示“本次整理方式”；仓库默认关闭，Token Plan 通道不提供 UltraSpeed。
- 用户每次明确选择“速度优先 · 费用较高”。页面展开官方价格和来源，切换档位清除此前的外部处理勾选，重新进入通知默认“使用当前配置”。加速选择不沿用到下一次请求。
- `processing_mode` 只接受 `configured` 或 `fast`。服务端在消耗限额、变更草稿或请求供应商前检查可用性；前端隐藏选项不能替代服务器校验。
- 加速通过配置副本，将本次提取与复核分别指定为 UltraSpeed，不修改共享 Settings，不切换计费端点，不影响其他账号、聊天或语音。维护者关闭复核时页面如实说明，档位选择不会擅自重新开启复核。
- 审计保存所选档位、实际模型和最大请求数。执行计量逐阶段保留实际模型、返回用量及未知用量标志；失败没有自动重试或更换档位。
- 接口缺省值为 `configured`；新前端面对未返回 `notice_modes` 的旧服务不发送新字段。

## 质量与有界输出

第一次完整加速调用耗时 42.437 秒，但复核的 6,144 token 几乎全部用于思考，没有完整答案，明确记为“复核未完成”。之后按模型调整复核预算：Flash 仍为 6,144，Pro 与 UltraSpeed 为 16,384；提取保持 20,000。预算包括思考及答案，不是实际收费量，也不代表一定用尽。此决策更新 ADR-006 的统一复核上限，输入预算与流式大小边界继续有效。

另一次完整调用耗时 46.140 秒，复核完整并指出期限缺失，但提取把明确期限只留在概况和引文，个人步骤没有日期。保留失败报告，没有放宽预设期限检查。现在输出契约要求每个步骤携带 `due_date`、`due_time`、`deadline_text`、`deadline_evidence`；未知值须显式为空。有效期限引文却缺日期或对应时刻时，服务器增加核实提示，不自动替本人选择日期。旧手工草稿继续兼容。

最终完整调用耗时 **39.438 秒**，提取 18.610 秒、复核 20.687 秒，两次请求、18 项预设检查通过。保留明确 `24:00` 跨日归一化、签章与确认前置、三项交付物以及不自动创建待办的规则。复核仍指出奖励发放被虚构为个人申报、纪律遗漏和榜题立项名额未表达，并对同一名额限制给出两条意见。原文确有相关条款，但并不意味着每条建议都应转成个人任务，本人仍须核对。

此结果表示链路完成并给出待核对草稿，不表示提取全对。各次调用的提示、预算、草稿和缓存不同，不能据此宣称稳定提速倍数、P95 或总体准确率。独立冻结通知集和真实学生验证门槛继续保留。

## 费用、界面与验证

最终样本返回输入 17,305、输出 15,035 token，其中缓存输入 1,408；按当天公开单价估算约 ¥1.379，未考虑优惠、税费和账单结算。这不是每次价格或供应商账单。思考正文不保存。

三种浏览器在 320／390／768／844 横屏／1440／1920 六组尺寸验证选项、价格、同意状态、实际 HTTP 路由和配置隔离。窄屏选择框至少 16 像素、44 像素高，为固定导航留出滚动间距。测试使用独立账号、数据库和模拟供应商，不使用正式库，也不追加付费模型调用。

没有新增数据库结构或运行依赖。当时的预览服务与浏览器复现脚本已在 1.20.0 清理，当轮结果和失败记录见 git 历史；真实模型脚本 `scripts/verify_business_notice.py` 仍须显式传入 `--live`。当前测试体系见 [TESTING.md](../TESTING.md)。
