# ADR-003：通知原文编号与期限证据绑定

状态：在 1.7.0 采用。日期：2026-10-18。

## 实际问题

使用项目内《大赛通知.md》和《校园通知智能转办助手_项目需求.md》进行真实 MiMo 调用，参与者身份及参赛意愿明确为合成输入。原实现耗时 221.218 秒后返回 502：模型输出结构完整，但把 Markdown 链接改写成显示文字，导致三处唯一引文未通过原文检查，整份草稿被拒绝。模型还把 `2026年10月19日24:00` 留成缺少时刻的候选。不能靠接口连通测试或合成短句证明这种业务材料能通过。

模型返回用量后，应用层验证失败却没有保存用量，也使失败请求的成本无法准确观察。既有严格引文检查仍有必要；把它改成模糊匹配会掩盖模型修改原文的问题。

## 决策

### 由程序登记引用，模型只选择编号

`app/notice_references.py` 在每次请求内依次登记 `R000001` 等编号，与当前原件的来源 ID、原始位置和连续原句绑定。模型输入同时包含编号与原文；输出 evidence 数组只需选择编号。长段按 1,400 字符的连续片段登记，保留各片段原位置，不静默裁剪非空材料。图片只登记现有的图片定位说明，仍把视觉观察和逐字引文区分。

服务器恢复完整 Evidence 对象后，继续执行现有来源 ID、位置和原文检查。未知编号拒绝；同列表重复编号去重。已有精确引文适配器继续接受严格校验，前端、待办及导出结构保持兼容。编号仅在当前请求的材料集合内有意义，不提供跨通知或跨账号检索能力。

模型不再重复输出个人计划、提醒、确认状态和私人备注等由程序控制的字段。八类事实、实际办理步骤和不确定性保留。提示词明确拆开“申请人取得签章／申请确认”与“单位实施审核”，避免把申请人的整个办理链误归为他人职责。

### 日期与时刻必须有同一依据

`app/deadline_evidence.py` 在明确完整日期之后解析对应时刻，以后继日期、未明年份日期、相对事件或句界结束绑定，防止借用另一节点的时刻。明确的 `24:00` 转换为次日 `00:00`，保留原期限表述；跨月、跨年与闰年使用标准日期运算。

相对日期先将带时区的发布时间换算为北京时间。无年份不补年份，无时刻不补 `23:59`；“收到材料次日”“缴费当天”等未知事件不替换为发布日。无法验证的候选清空相应日期或时刻并保留待核实说明。图片候选继续标为须对照原图核实，不把此文字校验器冒充视觉校验。

### 失败也保留已知用量

通知调用在读取供应商响应后先提取实际 usage。输出截断、结构或引文校验失败时，通过 AIError 传回已返回的输入／输出 token 数，并保存到该调用记录。未知或格式无效的数值保留为 null，不记成零、不按字符数推算费用。

## 为什么这样选择

- 保留严格原文检查：模糊匹配不能可靠区分显示格式变化与事实改写。
- 限制模型重复抄写：编号把机械复制交给程序，不新增摘要模型或自动修复请求；原文仍完整进入既有预算校验。
- 保留现有应用接口：原件、来源定位、草稿编辑、办理闭环和日历无需数据库迁移。
- 日期解析采用保守规则：不声称理解全部中文事件表达、跨句指代、任意时区或表格关系。复杂期限仍需要本人核对。

## 失败及扩展边界

编号只能证明所选材料存在，不能独立证明模型结论与材料语义相符。本人确认、不确定性和责任主体核对仍然必要；不自动建待办、不自动确认提醒。

供应商超时或断连时可能已经计费，仍由本人手动重试；不自动重发请求。HTTP 客户端的读取超时是网络等待限制，并非整个请求的墙钟总耗时保证。单一业务材料的前后两次观察不能用于推断整体准确率、P95 或固定加速比例。

当前登记按字符片段进行，极长跨段关系可能需要选择多个编号；后续若采用句界分段或表格单元格登记，必须保持原件定位、输入预算和完整性测试。没有为这次修复引入向量库、外部代理框架或新的运行依赖。

## 验证

`tests/test_notice_references.py` 检查 Markdown 原句还原、长材料保留、未知／重复编号和失败用量；`tests/test_deadline_evidence.py` 检查日期时刻绑定、午夜、发布时区与未知事件。已有图片、预算和草稿版本测试继续运行。

`scripts/verify_business_notice.py --live --label verified --keep-fixture` 在调用前保存原件 SHA-256 与预设检查，调用一次真实模型；生成记录保留在忽略目录的隔离库以供浏览器查看，不写入正式库。该脚本需要显式 `--live`，默认只准备验收记录。实际结果与限制见 [TESTING.md](../TESTING.md)。
