## 检查完整性

完整一轮必须包含：全部后端文件、全部 Node 前端用例、全部十二组通用浏览器检查、五组 Agent/附件/语音检查、OpenUI/布局/交互/恢复的三个浏览器引擎、GenUI 目录与评估、Python/npm 依赖审计、真实 HTTP 并发/重启/恢复、源码交付打包、生产容器启动及解析。

测试消费者按现有界面运行：移动状态下使用实际的状态选择框，折叠内容先通过公开入口展开，周日历与看板按当前纵向布局检查。保留真实保存、失败回滚、跨窗口冲突、撤销、刷新恢复、键盘和触摸操作、对齐及无重叠断言。

需要网络故障注入的页面按 Playwright 官方说明隔离 Service Worker，让注入请求实际抵达测试路由；持久推送另用真实 Service Worker 检查，模拟的仅为浏览器订阅和服务商投递，不声称真机到达。异步模块先加载，再以同步条件轮询布局与阅读位置，避免 Promise 对象被轮询器误判为已完成。

所有失败保留原始日志。诊断补跑用于定位问题，交付必须在最后一次改动之后重新执行完整一轮，并比较整轮前后的源码摘要。最终再核对同一 main 提交的 push CI 全部 jobs。

隔离检查显式关闭导入时自动读取本机 `.env`，保留正常启动和显式配置入口。后端分组与历史报告无关，确保本机及 GitHub 首次运行采用同一分组规则。分片有独立期限、逐用例进度和慢用例线程栈，旧 JUnit 在执行前清除，超时及缺失结果均不能通过。
