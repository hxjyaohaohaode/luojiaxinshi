# 试点链路与响应验收

## 业务依据

- 武汉大学统一身份认证要求按学生或教职工身份核验学工号、证件和联系方式。本站的手机或邮箱验证证明能够使用该联系方式，学院角色由已授权管理员核对并授予。实际学校账号激活仍在校方系统完成。[武汉大学账号激活操作手册](https://cas.whu.edu.cn/jhzn.html)
- 同一份通知可以有不同责任人、办理入口和截止日。2027 届本科毕业论文选题中，教师申报、专业负责人和学院审核、学生填志愿、教师选定学生是分开的步骤。只保存经过本人核对的行动和期限；通过站内协作取得的回执仍按站内来源展示。[测绘学院选题通知](https://www.sgg.whu.edu.cn/info/1380/46581.htm)
- 研究生、本科生和教职工办理的窗口与手续不同。缺失的资格、权限或附件保留待核实状态，并提供原通知及实际办理渠道。[综合事务服务中心服务事项](https://service.whu.edu.cn/info/1012/17611.htm)

## 试点操作

1. 管理员选择公开或邀请注册，并准备已验证可送达的手机和邮箱渠道。参与者经过验证码和密码设置后进入个人工作台，按需要补充个人条件。校内协作权限在学院工作台按已核对的身份和范围分配。
2. 收取来源、正文和附件后，按适用性、期限、条件与证据核对通知。参加者选择本人需要办理的步骤，再保存为待办、计划和提醒。校方更正经过核对后更新相应记录。
3. 学生可从待办发起站内协作，确认接收人及明确分享的文件版本。接收人可接收、退回补件和办结。发起人可补交或撤回。详情与提醒同时记录，原个人待办可继续独立跟进。
4. 同一账号从另一设备打开相同服务地址后，按服务器提交的版本刷新变化的模块。当前浏览器处于前台时检查间隔为三秒，同浏览器的标签可以在成功写入后立即发出刷新信号。断线重连、切回页面和离开编辑区会重新检查。打开的办理详情会显示另一端已保存的进度、材料版本和提交记录，同时保留正在填写的内容和已选但未上传的文件。保存仍以版本校验为准。
5. 通知、待办和日程列表可用条件请求复用上一份已验证的数据。每个响应先检查当前账号和会话。账号级设置包括个人条件、提醒偏好、日历和待办视图、动效与侧栏偏好；通知授权、推送订阅、当前浏览位置和正在填写的未保存内容由各自设备维护。已提交的草稿按账号和记录版本保存。

## 验收口径

- 浏览器脚本用独立 Cookie 和本地存储实测桌面、手机尺寸、接收人三个会话。分别记录提交 HTTP 状态与耗时、提交成功到另一端显示的耗时、编辑冲突和离线恢复。五秒是隔离本机前台的可见性目标，生产网络和设备仍需现场测量。
- 真实 HTTP 并发脚本按方法、接口、状态码统计样本数及延迟，分开记录成功、权限失败和冲突。发布容器、备份恢复和全部现有测试在同一份候选源码上执行。
- 直接查询已保存待办的总数可由服务器在同一事务完成并保留查询依据。需要材料、优先级解释、建议或多轮上下文时使用原有 Agent 路径。模型联调分开记录首段文字、互动控件可用、独立核验和最终保存，不混用离线夹具的时延。
- 试点部署方需按实际域名和运行环境检查 HTTPS、持久存储和恢复、短信及邮箱送达、设备后台提醒、来源可达性、授权人员范围和至少五天的使用记录。运行 `python scripts/pilot_preflight.py --production` 核对配置，再保存真实使用证据。
