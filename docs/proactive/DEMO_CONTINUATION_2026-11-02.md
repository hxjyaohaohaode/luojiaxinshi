## 新发现与修复

1. 空白会话首次发送会在 `drawMessages` 读取空的 `current.processing`，使消息停在本机队列。已改为统一的 `shown` 会话投影；浏览器刷新后原输入恢复、服务端取得回执，没有重新填写或生成重复用户消息。
2. 学院CMS附件需要原文章的Referer。无Referer时，实际下载地址返回HTML，原代码报正文结构不匹配。`notice_intake._read_link` 现在仅在同一公开域名携带已保存的父文章路径，删除查询参数和片段；逐次跳转继续检查域名和公网目标。跨域与私有来源不发送此头。
3. 《补充说明.pdf》和获奖名单PDF经真实读取取得1596与2736字。另一份盖章通知下载成功但没有文字层，实际为6页扫描PDF。
4. 新增 `pdf_visual.py` 与 `pdf_render_worker.py`，由单独、限时、限内存的进程渲染扫描/混合PDF的全部页面，包含批注和表单，保留原PDF与原来源ID。页码引用为“PDF 第 N 页（图像观察，非 OCR）”，不伪造OCR文字。
5. 真实6页文件暴露了旧4图硬上限。核对MiMo官方文档后，移除通知整理、办理助手和网络聚合中的这一硬限制；按照已有输入Token、文件字节与文档解析资源预算校验。所有页面均计入模型预算，超限明确拒绝，不静默丢页。
6. 资料库 `read_source` 按账号与当前范围加载PDF原件，生成页码证据，将相同像素提供给作者与独立核对。异步渲染后再次核对原件归属、哈希、状态及撤回，原始像素不写入长期历史或执行日志。
7. 引用到PDF某页时，完整材料预览带 `#page=N`；通知附件保留受账号保护的PDF原件预览入口。
8. 办理页增加真实变动记录与前置事项入口，材料、参与选择、跟进和反馈可就地定位。变动/前置未处理时不把“跟进到期”当作可以直接提交；“任一前置”已有有效完成项时不要求再做多余同级步骤。初始隐藏不相关的提交/提醒字段，实际阶段改变或原生校验错误会展开相应部分。
9. 浏览器实际操作发现前置事项完成后，下游列表仍可能保留旧约束。`displayTaskUpdate` 现在立即更新本项，再读取服务端的完整待办投影；按账号、页面和请求顺序防止旧返回覆盖新状态。已验证撤回完成后重新受限，再完成后解除约束，原有复核记录保留。打开变动前暂存办理草稿，返回不丢输入。
10. 上传附件的点击回调被分支预览的同名变量遮蔽，实际报 `preview is not a function`；已将分支数据改为 `branchView`，真实点击能打开附件。
11. 引用/收件状态/附件和新增表情按钮没有被完整纳入既有 Grid，重试按钮只有12px宽并被表情按钮遮挡。现在上下文各占完整行、五个输入控件各有位置。320/390/768/1366四种宽度下均检查实际命中、视口范围和横向溢出；重试按钮真实恢复收件成功。
12. 内嵌PDF在当前浏览器实际黑屏，改用受账号保护的整页JPEG预览，保留原PDF下载和原生打开。`pdf-preview` 返回完整页码清单，`pdf-pages/{page}` 返回对应原件页面；读取前后均核对归属和原件是否仍存在。不依赖原生PDF阅读器完成平台内分页。
13. 真实待办问答暴露 `workspace_read(tasks)` 只返回基础任务行，没有办理阶段/依赖/变更状态。现在复用网页使用的 `workflow.enrich_tasks`，一次读取返回同样的当前办理投影和可引用证据，不改写任务。工具说明明确区分个人办理状态与助手操作回执；测试核对页面一致性、前置完成后的刷新、待核实变动保留和跨账号隔离。
14. 进一步复现SSE结束问题：已有合法完成帧、最终用量和`[DONE]`，读取器仍等TCP EOF。现在按终止标记结束读取，由响应上下文关闭连接；没有完整finish_reason的工具仍不能执行。可控保持连接夹具中，旧代码在结束后继续等待，修复后16ms返回，保留最后用量；这不是对真实模型整体耗时的提速承诺。
15. 作者和独立核对共用 `TASK_STATE_POLICY`：本人标记完成优先于保留的阶段记录，前置约束、原要求变更和个人跟进分别判断。保留实际字段，不将阶段差异凭空升级为未完成或校方受理。

## 原始依据

- [PDFium Python API](https://pypdfium2.readthedocs.io/en/stable/python_api.html)：PDFium线程安全、页面/批注/表单与资源生命周期。渲染使用单独进程，不称为完整操作系统沙箱。
- [pypdfium2官方项目](https://github.com/pypdfium2-team/pypdfium2) 与 [PyPI](https://pypi.org/project/pypdfium2/)：版本与许可证；新增的是PDF解析能力，不是另一套Agent运行时。
- [MiMo图像理解](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/multimodal-understanding/image-understanding)：图像数量按上下文容量约束，未规定四图硬上限；本项目仍保留文件/文档/渲染/模型预算。
- [MiMo官方请求接口](https://mimo.mi.com/docs/api/text-generation/openai-api) 与 [思考模式](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/other/deep-thinking)：用于恢复诊断的请求格式。正式模型和思考/输出预算未降档。
