1.11.0 将模型意见与本人处理分开存储：逐条决策由本地校验，不再用一段总说明代替；确认记录可回查，导入历史明确不代表当前核实。没有增加模型调用、修改模型意见或把本人说明当作原文规定。见 [ADR-008](ADR-008-per-issue-human-resolution.md)。

## 执行链路

正式通知整理入口在 1.7.0 使用当前请求的原文编号登记：模型选编号，服务器恢复精确引句，再执行结构、来源及日期时刻检查；不增加摘要或自动修复调用。编号不能证明语义正确，仍须本人核对后才能形成待办。1.8.0 将办理建议放在模型任务附近输出，并在服务器拆成独立计划；兼容有界的全局待核实提示与相同重复建议，冲突或未知控制字段仍拒绝。该入口与下面的互动回答多阶段链路分别实现，详见 [ADR-003](ADR-003-notice-evidence-references.md)。

1. 从完整逻辑历史确定用户要求、可访问资料、是否联网、是否允许记忆及输出形式。
2. 根据当前账号和对话范围召回本人确认的记忆；保存原始历史，另行构造有预算的模型上下文。
3. 检索允许范围内的材料、通知、日程及个人条件；用户限制作用于实际检索，压缩摘要不能扩大权限。
4. 明确限定来源且仅要文字的短任务，可合并覆盖检查与写作；其他任务执行规划、覆盖检查和必要的补查。
5. 本地结构／逐字引文检查和独立模型复核通过后发布。未通过的草稿不冒充成品；修复有次数和无进展退出条件。

这些能力运行在默认启用的 `AI_GROUNDING=true` 证据链路。`AI_GROUNDING=false` 是保留的旧接口兼容开关：有历史压缩，但不执行长期记忆召回与独立事实复核；正式使用应保持默认设置。

## 短期上下文

`app/context_engine.py` 的 `context-v2` 在本地执行抽取，不增加摘要模型调用：

- 最新用户问题与已验证的界面输入必须完整保留；单条超过预算会拒绝处理，提示精简，不静默截断。
- 近期按完整问答轮次保留，避免留下没有问题的旧答复。其余空间按相关性及约束词选取旧用户原句。
- 相同固定约束只保留一次。历史相对日期带原消息北京时间，不把“明天”解释成今天的下一天；不同时间的相对日期不合并。
- 摘录标记为部分历史，可能被后续要求更正；新要求优先。旧助手文本不充当事实依据。
- 历史预算默认 36,000 UTF-8 字节，附有消息封装余量。这只是历史部分的应用预算，不是精确 token 数或整个模型输入上限。
- `report.context` 保存原始／打包字节数、消息数、摘录数、时间标注数及算法版本，不修改原消息。

一个会话最多接受 2,000 条逻辑消息、400 万字符历史。完整记录继续保存在 SQLite；这不表示所有历史都进入每次模型请求。通知正文与附件仍走原有输入完整性和预算规则，不能用历史压缩绕过正式通知输入上限。

## 长期记忆与项目

用户从“个人与账号 → 我的记忆”管理项目和条目，从聊天“＋ → 项目与记忆”绑定范围。保存需要本人确认；系统不会把模型猜测、通知正文或每条聊天自动写成长期事实。

| 范围 | 使用条件 |
|---|---|
| 通用 | 同一账号所有允许记忆的对话，可跨项目使用 |
| 项目 | 对话明确绑定该项目；项目名称与说明也作为本人提供的背景 |
| 专题 | 对话明确选择同名专题，最多 8 个 |

记忆类型为偏好、约束、已确认决定和本人提供的信息。先按所有者、启用状态和范围过滤，再按置顶及词项相关性选择；偏好和约束可跨具体问题复用。召回总量最多 12 个条目（含项目背景），内容及封装预算最多 8,000 UTF-8 字节。当前是有界词项检索，未部署 embedding 或向量数据库，不能保证召回所有语义近似内容。

每个账号最多 100 个项目、500 条记忆，手工创建与追加导入都检查已有数量。修改、停用、删除和对话范围更新使用乐观版本检查。生成中不能切换当前对话范围。新分支继承项目、专题和启停状态，但后续可以独立修改。

记忆可以随时停用或删除；用户明确禁止使用记忆时，该限制持续到用户明确恢复。记忆只属于用户背景，不获得系统指令权限，也不能替代原通知。本轮明确要求及正式来源优先，不自动改写已确认条目。

`memory-policy-v1` 在相关性排序前执行有效性过滤。可设置 `valid_from`、`expires_at`，未生效、到期及停用内容不召回。同一显式 `semantic_key` 的优先级为项目 > 专题 > 通用；最高优先级有不同内容时全部隔离，不能猜测哪条正确或回退到更低优先级。相同值只使用一个条目。没有键的自然语言内容不声称已完成语义矛盾检测。

完全重复且来源、范围和策略一致的创建复用原条目；来源不同则保留独立溯源。目录展示当前同范围冲突，明确保留某项时需要提交完整成员版本，事务内停用其余项。跨专题同时启用导致的冲突在对话预览中说明，可编辑或停用相应条目。前端按设备时区输入和显示有效期，服务端保存 Unix 秒。

对话设置可预览当前已保存范围内的候选，以及未启用、过期、未生效、冲突或被具体范围覆盖等排除原因。预览不等于实际问题最终召回；后者仍受相关性、条目数和字节预算限制。

后续生成会检查旧回答曾注入的记忆版本，即使该旧回答没有内联记忆引用。任一记忆已变更、撤销或不再属于当前范围，就从新模型历史中排除该旧回答；页面中的历史记录仍保留。用户自己在聊天中写过的内容仍属于会话历史，关闭长期记忆不等于抹除聊天。

## 持久化、迁移及接口

主数据库版本保持 4，增量 `memory_schema_version=2`：

| 表 | 责任 |
|---|---|
| `memory_projects` | 账号所属项目、说明、版本与时间 |
| `personal_memories` | 所有者、范围、类型、内容、启停、优先级、来源对话和版本 |
| `conversation_context` | 对话项目、专题、记忆开关及独立版本 |
| `memory_policies` | 记忆有效期与显式互斥键，随条目级联删除 |

删除项目会删除该项目的专属记忆并解除对话绑定，保留对话；删除来源对话会删除通过该对话保存的关联记忆。完整 SQLite 备份保留状态。JSON 导入重映射项目并将记忆停用，来源对话关联清空；本人核对后启用。再次导入修改过的同一项目不会覆盖已有项目。缺失项目、超出容量或非法字段会回滚本次导入。

| 接口 | 功能 |
|---|---|
| `GET /api/memory` | 当前账号的项目和记忆 |
| `POST /api/memory/projects` | 创建项目 |
| `PUT /api/memory/projects/{id}`、`DELETE` | 带版本修改／删除项目 |
| `POST /api/memory/items` | 创建本人确认的记忆 |
| `PUT /api/memory/items/{id}`、`DELETE` | 带版本修改、启停／删除记忆 |
| `POST /api/memory/items/{id}/resolve` | 核对完整冲突成员版本，保留选定条目并停用其余项 |
| `GET /api/conversations/{id}/context` | 查看对话范围 |
| `PUT /api/conversations/{id}/context` | 带版本修改对话范围 |
| `GET /api/conversations/{id}/memory-preview` | 当前保存范围内的记忆候选和排除原因 |
| `GET /api/executions` | 本账号最近 50 次处理记录，不返回凭证或内部令牌 |

以上写入复用登录、账号归属和 CSRF 检查。明显的 API 密钥或私钥不允许保存为记忆。

## 提示词与速度

`prompt_version=evidence-memory-v2`。材料、本人背景、用户原句、模型草稿和审查意见分开标注；审查意见不能成为新的事实来源。复核提示按回答形式装配，纯文字任务不再携带大量交互组件规则；只有实际包含网页或图片时才加入对应要求。

`focused_text` 仅用于明确禁止联网／限定消息、要求纯文字、检索无截断、来源不超过 8 个、选取文字不超过 12,000 字且不含图片的请求。覆盖检查与写作合为一次 Pro 思考调用，随后仍由第二次 Pro 思考调用独立复核。复杂回答保持完整证据链路；未通过检查不能作为提速方式直接发布。

默认 `AI_STAGE_SUMMARIES=false`，阶段提示直接使用真实执行状态。启用可选的模型状态摘要仍有测试覆盖，但普通运行不为改写进度提示额外付费。此次没有降低主模型、关闭独立复核或接入其他模型供应商。

## Harness 与循环

`app/harness.py` 的 `harness-v2` 用请求级 ContextVar 记录阶段耗时、实际调用数、模型、思考开关、输入／输出／推理 token 数、缓存命中 token 数和退出原因。保存于对应回答的 `reply_grounding.report.harness`；不保存模型内部推理正文、密钥或额外的提示词副本。API 未报告用量时计量只代表已取得的数据。

修复最多 5 次生成、3 次协议修复、1 次语义修复；相同问题与相同草稿重复出现即停止。退出原因区分 `verified`、`no_progress`、协议／语义／生成上限、取消与请求失败。外层仍执行工作流总时限、取消和处理令牌校验，迟到结果不能覆盖新一轮回答。

`context-snapshot-v1` 固定获准的上下文状态，在规划、检索后、写作与核验后重检，并在最终提交事务再次校验。有效记忆过期、冲突或版本变化同样使旧结果失效。个人资料在请求授权快照与初始生成快照之间变化也会拦截。账号资料库检查目前较保守，权限范围内未采用资料的变化也可能触发重试。失效记为 `context_changed`，保留问题和材料，不自动改输入后继续外发。

`execution_schema_version=2` 持久保存进程租约、执行阶段与终态。45 秒租约、10 秒心跳用于发现失联，恢复只清理旧任务自身状态；备份恢复也会标记未完成执行。前端“模型与处理记录”提供原记录入口。没有模型调用中途续跑、检查点重放或外部观测上传，不承诺调用恰好一次。并发槽和主动取消仍为进程内实现，部署继续单实例。

## 验证入口

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_memory_context.py
.\.venv\Scripts\python.exe scripts/verify_personalization.py --live --long-history
```

真实模型脚本必须显式传 `--live`，使用隔离临时数据库和合成材料，不读取正式账号。当轮另有依赖 `scripts/mvp_preview_server.py` 的浏览器脚本，覆盖三种引擎、六组尺寸和九类页面／表单，包括有效期、模型通道和执行记录；该脚本已在 1.20.0 清理，见 git 历史，当前浏览器回归入口见 [TESTING.md](../TESTING.md)。真实调用不是随机化性能实验或真实用户效果评价。

1.8.1 将通知处理纳入真实阶段与标量诊断：状态随执行租约判断，SSE 仅接收完整候选，所有校验通过后才发布草稿；失败不自动重试。`execution_metrics` 记录首段答案等待、模型请求与校验耗时及实际返回用量，未知值不记作零，思考正文不保留。参见 [ADR-005](ADR-005-notice-streaming-and-measurement.md)。

真实通知评测的离线入口为 `scripts/evaluate_mvp.py`：固定开发／测试分组、原件、人工答案和计分器版本，核对原始草稿与人工裁定后按全部冻结案例统计。它不调用模型，也不代替人工语义标注或真实用户试验，格式和命令见 [评测协议](mvp-evaluation/FORMAT.md)。
