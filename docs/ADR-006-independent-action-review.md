# ADR-006：通知行动的独立语义复核与本人处理

日期：2026-10-18。实现版本：1.9.0。状态：采用。

## 问题与证据

精确引文只能证明原句存在，不能证明模型正确理解了谁来办理、是否必须办理、具体手续与材料。1.8.1 的真实赛事草稿通过了结构、日期和 13 项预设检查，人工复核仍发现把奖金发放写成可选申请。将其直接视为完整正确的草稿，会把核对负担留给学生。

本次对同一保留草稿进行独立模型复核，发现了培训被列为必办、奖金申请程序缺少原文支持，以及交付材料遗漏。后者分别出现在步骤与概况中，共四条意见。必要的本人申请签章和向发榜单位申请确认未被误判。复核仍可能遗漏、误报或返回不合格结构，意见不能成为新的正式要求。

## 决策与调用边界

- 默认保留 `mimo-v2.6-pro` 开启思考进行提取；完整接收并通过现有校验后，由 `mimo-v2.6-flash` 开启思考核对语义。最多两个供应商请求，无自动重试、自动改写或无限修复循环。此决策替代 ADR-005 的默认单请求通知流程。
- 新模块 `notice_semantics.py` 只接收本次原始材料、必要个人条件、已校验的事实与行动建议。事实和步骤不重复携带引文副本；私人备注、提醒及核实说明不进入复核。图片存在时才加入图片说明，并沿用当前图片边界。
- 提示检查责任主体、必办与可选、是否虚构手续、条件、依赖、遗漏、期限和适用性。模型需逐个覆盖步骤，问题须指向本次登记的原文编号。程序拒绝不存在的步骤、假编号、重复或缺失的覆盖项、截断和不合格 JSON；随后由程序还原原句。
- 随后的真实联调揭示只围绕既有步骤复核仍会漏掉附件交付物。最终 `notice-semantics-v2` 先逐份整理原始材料的要求与覆盖情况，再核对步骤。程序检查每份原文均有记录、各自引用属于该份材料、标记遗漏或不确定时确有对应意见；页面允许展开逐份核对记录。该完整性校验不等于对摘要语义正确性作保证。
- 独立复核也有输入预算与 6,144 输出预算。超限不发送第二次请求；复核失败保留已校验草稿，状态明确为“复核未完成”。缺少完整意见绝不计为通过。
- 进入复核前再次检查通知版本、处理令牌、个人条件与执行租约；失效时阻止第二次调用。最终保存继续在事务内复查版本，避免中途变化后发布过时草稿。

## 本人确认与页面行为

页面显示每条意见、相关步骤和精确原句。步骤重排采用原始步骤身份定位，手工增加的步骤不会冒充原生成步骤。显示已知分类枚举时转为“必办”“可选”等学生用语，存储意见和原文不被改写。

有意见或复核未完成时，确认请求必须包含至少八个字符的核实与修改说明。学生可修改步骤、不保存相应步骤，或说明意见不适用的原文依据。服务器依据自己保存的复核状态检查，客户端不能伪造“已通过”绕过；重复已完成确认仍保持幂等。说明随草稿暂存，并与原始意见、实际保存的任务 ID 一起进入修改记录。

这是可回查的人工处理记录，不是自动判定每处问题已经改对，也不代表学校核准。没有发现问题同样需要原有逐项确认；历史草稿和维护者关闭复核的草稿明确标为未独立复核。

新增页面沿用原通知布局。窄屏正文换行、编辑框至少 16 像素、操作按钮至少 44 像素，意见与证据可折叠，跳转给固定导航留出空间。新功能没有增加第三方前端组件或框架。

## 计量、状态与运维

沿用执行扩展版本 2 的 `execution_metrics`，每个阶段保存白名单模型、用途、状态、是否发起，以及供应商实际返回的有限数值。总用量是已知值之和；有已发起请求缺少用量时标记不完整，不能把未知费用写成零。只保存思考 token 数，不保存思考正文。旧 `ai_calls` 继续表示一次通知整理，阶段详情区分实际模型和请求数。

`AI_DAILY_LIMIT` 仍限制通知整理次数，不是供应商请求次数；默认每次整理最多两个请求。设置 `NOTICE_SEMANTIC_REVIEW=false` 可关闭新增阶段，`MIMO_NOTICE_REVIEW_MODEL` 配置复核文字模型；计费通道与模型兼容性仍按统一目录验证。外部处理确认会说明最多两个请求。没有新增数据库表或运行依赖。

## 实验限制与不采用的捷径

- 改为 Flash 提取的真实材料调用约 136 秒，但漏掉签章、确认与提交的必要依赖，未采用为默认提取。
- 保留草稿的 Flash 思考复核约 46 秒，找出上述四条意见。关闭思考的另一次复核约 18 秒，但遗漏交付材料，还误判合法职责与步骤，未采用。
- 十二个预设合成案例最初有一个“不应报问题”的标签错误：原句仅规定申请资格，草稿却标为必办。模型指出的义务问题有依据，原始报告保留。修正可选分类后仅重测条件一对，其中有一例结构不合格而被拒绝；不能宣传成全数通过或总体准确率。
- 初版完整两阶段真实联调为 305.282 秒、两个请求、15 项预设检查通过，但人工复核发现仍漏掉本人交付与附件中三项交付物。该结果与原始输出保留为反例，不宣传成完整质量通过；逐份原文复核的后续诊断单独保存，不能和初版时间拼接成一次端到端性能结果。

新增复核有质量检查价值，也增加时间与用量；不同调用的服务等待差异很大，不能把单次结果称为稳定提速。真实材料与合成账号、原型测试与真实学生实验继续分开。逐次证据、最终工程检查和本机升级记录见 [TESTING.md](../TESTING.md)。
