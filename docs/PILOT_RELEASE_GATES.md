# 试点容量与工程发布门槛

复核日期：2026-11-14 UTC。对应 LJ-122／124／127／128。

**本文是本轮可审阅的工程建议，不是院方批准、正式用户规模、服务等级承诺或已经通过的生产验收。** 未填写的真实来源、设备、人员、费用和期限一律保持待确认。实际运行结果由冲刺验证记录另行保存，不能从本文中的目标数值推导“已达标”。

## 1. 分批范围

| 阶段 | 工程建议范围 | 进入条件 | 明确不能据此推断 |
|---|---|---|---|
| 准备 | 隔离合成环境；不连接生产用户库，不发真实邮件、Push 或模型请求 | 固定待发布代码、依赖锁与构建；执行本文件的本地门禁，登记部署与回退信息 | 合成账号不是实际学生或老师；配置存在不是外部渠道已接通 |
| 首批 | **最多 5 名真实参与者**，身份与材料范围由实际试点负责人确认 | 对应提交的工程门禁通过；每个启用来源和渠道有实际授权及验收；用户理解原文、个人记录和回执的区别 | 这是建议的受控试点规模，不修改系统注册容量，也不说明系统只能容纳 5 个账号 |
| 扩大 | **最多 10 名真实参与者** | 先在隔离环境执行 **10 人并发**的固定合成负载并达到全部门槛；再核对首批真实故障和外部条件，负责人明确确认扩大 | 10 人并发测试不是 10 名真人研究，也不是未来全院并发能力证明 |
| 后续 | 暂不预设更大人数 | 收集真实日量、峰值、队列、设备和成本，再提出下一档负载及容量决定 | 不将数据库允许注册的账号数、单账号容量或 1 万条查询样本视为并发能力 |

首批和扩大阶段都使用 **每日每人 20 条收件**作为工程负载档：5 人对应 100 条／日，10 人对应 200 条／日。这是测试输入和观测基线，尚未获实际院方确认，不是学生配额、实际每日收件量或自动删除策略。实际试点若存在集中发文、附件、长文或批量补发，须另录峰值和数据分布，不能只重复均匀小文本测试。

容量配置与已实现的事务门禁见 [app/usage_limits.py](../app/usage_limits.py)、[app/config.py](../app/config.py) 和 [校园容量与事项归组契约](CAMPUS_CAPACITY_AND_MATTERS.md)。提高容量字段不会构成扩大试点的依据。

## 2. 必须逐项达到的工程门槛

以下为本轮建议的准入标准，后续若需调整，应记录原因、批准人、适用环境及新旧标准；不能在看见失败结果后悄悄降低门槛。

| 项目 | 准入标准 | 实际证据及计算口径 |
|---|---|---|
| 正常非 AI CRUD | **P95 < 1,000 ms** | 对固定负载中预期成功的普通读写请求分别记录样本、路由、P50／P95／最大值；并记录总体。不能用静态资源或预期拒绝请求稀释正常业务延迟。登入、文件解析、模型与外部供应商另列，不混成一个“全部快速”的数字 |
| SQLite 写锁等待 | **`BEGIN IMMEDIATE` 等待 P95 < 100 ms，0 次获取失败／超时** | 使用数据库连接处的真实计时，报告等待与持有两个指标、采样数量、是否达到环形缓冲上限及进程启动时间。不是从 HTTP 延迟反推锁等待 |
| 鉴权与数据隔离 | **全部测试断言通过** | 同账号正常读取、跨账号／跨学院拒绝、直接链接、已撤权、注销／恢复后失效会话；记录预期 401／403／404，不能把越权被拒当业务失败 |
| 幂等与旧版本 | **全部测试断言通过** | 双击、并发、响应丢失重试不重复创建业务动作；旧版本返回预期 409，输入保留；事务回滚不留半条数据 |
| 时间、原文及证据 | **全部相关断言通过** | 正式截止／活动窗口与个人安排分离，缺时刻不补 23:59，候选不改变正式事实，结果／公示绑定当前原文，跨年度不串事项 |
| 完整工程回归 | **无未处理失败** | 当前冻结提交执行全部后端、前端 Node、可重建构建、三浏览器及声明支持的平台 CI；保留失败与修复轨迹，不以筛选少量通过用例替代完整结果 |
| 重启／恢复／回退 | **对应记录可重复复核** | 已确认记录保留、旧会话和过期授权不复活、备份结构及完整性通过；记录实际耗时与丢失窗口，尚未测到就记未知 |
| 外部服务状态 | **未知不得标“已接通”** | 配置存在、记录的连接成功、实际端到端验收三层分开；供应商接受不代表本人收到或设备展示；暂停、失败和覆盖不足可见 |

锁等待与持有的实现位于 [app/db.py](../app/db.py) 和 [app/runtime_metrics.py](../app/runtime_metrics.py)。现有计时保留本进程每类最近最多 4,096 个样本，同时报告总观测数；重启清零。应在被测进程停止前保存指标。样本不足、计时未观测或缓冲区覆盖范围不清时不能写“锁等待达标”。[管理员就绪](../app/observability.py) 与 [运维监测](../app/operations_monitor.py) 只显示可观察到的范围。

P95 应说明分位计算方式和样本数量；样本很少时不以漂亮的单次结果代替稳定性。1 万条查询微基准、单账号容量、10 个并发合成账号、真实校园日常使用是四种不同证据，应分别记录。

### 固定隔离负载的复现入口

脚本 [verify_local_runtime.py](../scripts/verify_local_runtime.py) 使用临时目录和真实本地 HTTP 进程；合成账号、文本通知、双任务、冲突／越权、幂等重试、重启和恢复均在该夹具内执行，报告明确 `synthetic_test:true`、`live_model_calls:0`。不要把命令改成对生产库或真实参与者发送负载。

```bash
CAMPUS_AUTO_LOAD_ENV=0 .venv/bin/python scripts/verify_local_runtime.py \
  --users 5 --notices-per-user 20 --output artifacts/pilot-runtime-5.json

CAMPUS_AUTO_LOAD_ENV=0 .venv/bin/python scripts/verify_local_runtime.py \
  --users 10 --notices-per-user 20 --output artifacts/pilot-runtime-10.json
```

上面的输出路径是待执行／复核产物的位置，不是本文提前宣告存在或通过的报告。应使用 `operations` 中预期正常请求的数据和 `database_locks_before_restart` 作门槛核对，而不只看脚本最后的 `result`。目前脚本的业务通过也不自动表示本文件每项性能目标全部达标。实际总账应写入每项实测值及 pass／fail／unknown。

完整用例发现与计数使用 [audit_full_suite.py](../scripts/audit_full_suite.py)，前端浏览器门禁使用 [run_browser_checks.py](../scripts/run_browser_checks.py) 及 [verify_sprint_ui.mjs](../scripts/verify_sprint_ui.mjs)。相关权限、时效、来源缓存、分发与协调合同见 [test_sprint_official_time.py](../tests/test_sprint_official_time.py)、[test_source_cache_policy.py](../tests/test_source_cache_policy.py)、[test_group_context_candidates.py](../tests/test_group_context_candidates.py)、[test_campus_sprint.py](../tests/test_campus_sprint.py)、[test_notification_coordination.py](../tests/test_notification_coordination.py)、[test_push_delivery.py](../tests/test_push_delivery.py)。这些文件存在不是它们在某次冻结提交上已执行通过的证明。

## 3. AI 与费用单独验收

AI 处理不纳入普通 CRUD 的 1 秒目标。应另外记录模型／版本、原件覆盖、实际请求次数、延迟分位、超时／取消／断流、已返回用量与未知用量；遇未知账单不能推断“没有计费”。独立人工标准与冻结样本流程见 [MVP 评测格式](mvp-evaluation/FORMAT.md) 和 [evaluate_mvp.py](../scripts/evaluate_mvp.py)。合成答案或开发者自己填写 `human_independent` 不构成独立校园准确率。

**真实预算未确认前，不启用自动批量模型处理或为试点自动扩大发送额度。** 真实调用保持本人对该次动作的明确确认；实际供应商、套餐／按量通道、每日预算、费用负责人及停止条件须登记后，再决定是否允许具体范围的自动处理。这里是发布准入条件，不声称系统能从 API key 推断付款权限或账户余额。

现有额度上限由 [app/config.py](../app/config.py)、[app/usage_limits.py](../app/usage_limits.py) 和 [app/notice_automation.py](../app/notice_automation.py) 执行；运维面板的额度计数是应用计数，不能冒充供应商账单或剩余额度。邮件／短信／Push 实际费用、收件权限和设备同意也须独立确认。试点人员同意收件不自动等于同意将全部群材料发送给模型。

## 4. 真实范围登记表

下表为空白验收记录结构，**没有预填院方、人员、设备、供应商、费用或完成状态**。只有有实际证据的一方才能填写结论。

| 必填项 | 应记录内容 | 缺失时处理 |
|---|---|---|
| 发布身份 | 待发布 Git SHA、构建产物标识、依赖锁、CI run URL、目标环境及实例 | 不将其他提交的测试套用到本次发布 |
| 真实负责人／参与者 | 实际负责人与职责、首批人数、授权范围、批准扩大者 | 不扩大至 10 人或更大规模 |
| 真实使用负载 | 每人日收件、集中峰值、正文／附件类型与大小、并发动作、最长排队时间 | 继续工程建议档，不能宣称已匹配学校实际高峰 |
| 来源授权与覆盖 | 官网栏目与原文范围、实际读取时间、QQ 群主／成员订阅、公众号发布方授权等 | 未授权渠道使用真实人工导入，不能挂绿色自动同步 |
| 设备与提醒 | OS／浏览器版本、前后台／锁屏／关闭／断网恢复条件、本人设备授权与实际展示结果 | 保留“未验证”，以站内记录说明能力边界 |
| 外部服务与费用 | 真实服务账号、可用通道、额度／预算／费用负责人、停止阈值；不写密钥 | 不运行自动批量或费用不明的真实压力负载 |
| 数据与支持 | 实际保留期配置、备份位置与访问权、联系入口、故障接手人与响应安排 | 保持原隐私契约，不能临时发明删除承诺或无人接手的 SLA |
| 现场验证 | 实际日期、场景、用时、原文样本、问题、复核人及单位验收结论 | 继续记为未完成，不能由 CI 合成数量替代 |

现有 [pilot_preflight.py](../scripts/pilot_preflight.py) 明确区分“配置可供检查”和“外部验收未评估”，并保留**累计不少于 5 天**现场实践或场景验证、书面记录及发榜／验证单位验收结论的要求。没有依据将“累计”改成“连续”，也不将赛事实践天数设为学生产品使用门槛。

## 5. 保留期、升级与回退

数据保留沿用 [隐私和注销实现](../app/account.py) 与 [运维文档](../OPERATIONS.md)：自动备份默认 **7 天**，实际读取 `BACKUP_RETENTION_DAYS`；已有通知正文、本人任务和原件没有因为本轮试点而新增“到期自动删除”规则。通知删除／注销及对方最小脱敏留存、文件授权回收按现有契约执行。备份在服务运行时轮换；停机不会执行清理，手工备份和另存快照由维护者按约定期限处理，不能许诺历史副本即时全部消失。

升级前使用现有在线备份取得一致性快照，并保留**与该快照兼容的旧代码、依赖和配置记录**。先在新目录恢复验证，再进入首批小范围。具体命令和版本门禁见 [OPERATIONS.md](../OPERATIONS.md)、[app/backups.py](../app/backups.py) 与 [manage.py](../manage.py)。旧程序不得直接写已经升级的新数据库。

出现以下任一情形即停止扩大范围：越权读取、幂等重放产生重复业务动作、材料／提交回执丢失、正式时间被无依据改写、未经本人允许外发、数据库锁超时，或本文件性能门槛失败。先保留失败证据、当前数据快照和修复前后版本；必要时关闭受影响自动处理／外发，再按对应旧快照和代码恢复。不要通过删除问题记录、清空队列历史或撤掉门禁制造成功。

回退前后记录实际开始／完成时刻、恢复耗时、最后可恢复记录及升级后新增记录的处理结果；**恢复旧快照可能丢失快照之后的写入**，因此必须先保全当前库并明确差异，不能承诺“零丢失”。恢复后旧会话、校园权限、设备与外发同意、来源及人工验收证据的复核按现有恢复规则执行，不能用旧快照自动复活授权。

## 6. 发布记录如何判定

每一轮记录至少包含：提交／构建标识、环境、负载档、实际样本数、正常 CRUD P95、写锁等待 P95 与失败数、锁持有时间、全部安全／幂等断言结果、外部服务状态、数据恢复结果及剩余条件。门槛任何一项为 unknown 或 fail，就保留在当前准备／小范围阶段，不能把“脚本能启动”或“存在配置”写成全量发布准入。

只有本次冻结代码的工程证据完整、实际试点范围和外部条件得到确认后，才建议在对应人数档进入真实小范围使用。CI、源码、合成负载、真机结果、独立人工评测和单位验收始终分别列出。
