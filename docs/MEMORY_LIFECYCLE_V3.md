# 记忆生命周期 v3：形成、调用、纠错和遗忘

本轮针对前版“把个人信息存下来”与实际 Agent 工作之间的缺口重构。数据仍在现有 FastAPI / SQLite 事务中，schema 升级到 3。来源仓库及固定版本见 [源码审查](MEMORY_SOURCE_REVIEW.md)，具体测试结果见 [TESTING.md](../TESTING.md)。本文件描述已接入的行为和边界，不把设计参考说成安装了 13 套框架。

## 1. 分层和形成规则

| 层级 | 形成方式 | 使用与退出 |
| --- | --- | --- |
| 仅本轮条件 | 用户明确说“仅本轮”“仅本次”，或 Agent 提出受限 lifetime | 仅最新用户消息所在轮次可用；下一轮退出调用，保留期内仍可查看和主动遗忘 |
| 会话短期 | 今天的计划、临时约束、尚无长期依据的信息 | 同一账号、会话及消息形成时的项目/专题组合；默认 7 天，可设 1–90 天；活动只刷新当前范围且尚未过期的内容 |
| 工作记忆 | 会话目标、当前请求、决定、待澄清、已报告进展和下一步 | 按会话与项目/专题组合分开存储；增量合并栏目，保留目标；人工可编辑、锁定；无有效会话片段时自动栏目不再沿用 |
| 长期个人信息 | 明确稳定原话、本人手动确认，或不同会话的重复稳定依据 | 先检查通用/项目/专题权限，再检查版本、审核、时效、来源、跨会话开关和适用场景 |
| 经历记录 | 用户历史经历、个人办理状态等 | 与长期偏好分层；默认 30 天到期复核，可设 7–365 天；不作为校方确认或当前任务状态 |
| 派生摘要/方法 | 本轮 Agent 提议；可选的后台语义复盘 | 保留来源 ID 和版本，先待核对；来源变化、失效、撤销或不可用时暂停依赖内容 |

“今天使用英文”不覆盖长期中文偏好。“这个项目必须离线”没有选定项目时先放会话；多个专题而无明确归属时也不猜全局。单一专题的晋升保留该专题；多个专题必须由本人明确选择。历史消息保存形成时的范围与学习许可，后续切项目不会改变旧信息的归属。迁移前缺少范围证据的旧消息，整理后只能暂存并等待人工选定范围。

自动晋升只处理保留期内、不同会话的至少两条相同稳定语义槽原话，同一会话反复说不增加独立依据。每轮最多 8 条。存在同类不同值时先待核对；已停用、冷却或待核对的相同记录不因重复出现而自动复活。模型看过多少次、自己使用多少次都不构成用户确认。

短期每会话最多 80 条，工作检查点最多保留 30 版。长期每用户 10,000 条、单条 2,000 字符的既有上限继续生效。达到容量上限不会丢弃聊天消息。

## 2. Agent 使用路径

调用链为：用户权限与本轮限制 → 消息来源范围 → 生命周期/来源依赖过滤 → 查询与会话指代扩展 → FTS/BM25、窄语义槽和来源关系候选 → 按名次融合、时效与实际反馈排序 → 去重及上下文预算 → 发布前检查实际使用版本。

“继续”“下一步”可以借用当前范围内的目标和最近请求解释查询。置顶只对已相关候选调整名次，不让无关信息强行进入回答。语言与表达偏好可通过明确的语义槽匹配，但同轮默认最多 2 条表达偏好，避免挤占业务信息。适用场景提示只收窄调用，不产生访问权限。

经历与任务记录需要明确的回顾、个人进度或具体事项意图；通用的“如何申请”不会仅因词相似就灌入旧办理状态。关闭日程来源时，物化成记忆的任务记录及其派生内容一并排除。相同权限用于 Agent 修改和派生操作，不能猜 ID 绕过召回权限。

长期记忆最多 12 条、序列化预算 8,000 字节，包含实际发送的记忆元数据。工作正文另有 6,000 字节上限；会话条件、操作回执等控制字段分别有条数上限，不把 6,000 字节说成全部控制字段的合计大小。融合后最多 512 个候选进入多样性重排，已重复、已达到类型上限或超出剩余预算的候选提前排除；业务操作中的“先做 A 再做 B”不会仅凭顺序表达就被当作全局回答风格。完整修改历史、审计和导入档案不随回答发送。当前仍采用本地词法与窄语义槽检索，没有部署稠密向量服务；跨表达的开放领域语义召回是明确的能力边界。

长期开关允许跨会话时，单条还必须允许共享；关闭单条共享后仅来源会话可用。项目/专题边界始终保留。工作记忆与短期事实不会因为开启跨会话开关变成跨会话事实。

## 3. Agent 写入与人工控制

Agent 在同次回答内可提出 `remember/update/archive/derive/checkpoint/use/forget`，`lifetime` 可为自动判断、仅本轮、会话或长期；`applies_to` 提供有限的适用场景。服务端逐项验证当前用户、当前消息原话、形成范围、目标版本、来源权限、人工锁定与遗忘标记。

`checkpoint` 的 `working_sections` 按栏目合并；省略栏目保留原值，显式空列表才清空。已确认决定和已完成进展需要用户原话依据；下一步仅代表建议，不能伪装成真实工具执行。`use` 必须引用实际提供给本轮回答的记忆，不能凭空上报采用。

推断改写、派生、时间条件及修改锁定正文进入待核对。回答失败、取消、过时或校验失败不提交模型操作；用户原话的保守摄取是独立事务，不能混同为模型推断。临时写作要求可在本轮生效，不构成长期保存。

界面提供会话片段查看/编辑晋升/遗忘、层级、跨会话共享、适用场景、冷却/归档、保留期与后台复盘设置。本人编辑、人工接受和历史恢复有版本校验，锁定优先于自动改写。未知历史范围的晋升必须明确选择通用、已有项目或专题，不能默认为全局。

## 4. 使用反馈与自我整理

每次完整回答分别记账：提供给模型的记忆、Agent 报告真正采用的记忆、本人反馈。用户可以在“这次回答的记忆使用”中选择“有帮助”“这次不适用”“内容已过时”。反馈需要真实回答与记忆归属及当前版本匹配；重复点击覆盖同一反馈，不累加刷分。“已过时”暂停调用并等待重新确认；单次不适用只调整相关性，不自动篡改正文。

本地整理默认开启，不调用模型：清理过期会话、检查自动记录复核期、不同会话稳定陈述晋升、维护持久队列与分类概览。正在生成回答的账号暂缓后台整理；有新变化时进入下一轮，无变化不反复全量整理。单轮处理上限和事务避免无限整理。

可选语义复盘默认关闭，开启位置为“生命周期与遗忘设置”。开启后使用现有摘要模型，且只处理已有外部模型授权、账号空闲、记忆和个人档案允许的对话。默认每天最多 2 次，可设 1–8 次，同时消耗既有 AI 每日额度。复盘次数按 UTC 自然日计算，应用原 AI 额度沿用中国时区规则。每次最多 16 个有效原始来源，最多提出 4 条带来源的摘要/方法；不将之前自动生成的概览反复喂回来自证。

复盘持久保存输入指纹、状态与用量；调用在事务之外进行，结果提交前再次校验来源、版本、开关和账号状态。输入变化则取消，结果永远先待核对，不自动改写原始事实。失败或中断不自动再次请求付费模型；未知结果也不会当作成功。删除来源会清理含该来源的复盘输入快照。

## 5. 遗忘、冷却与历史回放

冷却和归档保留原文，但暂停调用。自动记录到复核期后可以冷却，人工维护/锁定内容不自动冷却；没有用“被模型看过”来续期。经历默认 30 天；其余自动非永久信息按类别复核（偏好/约束/方法通常 180 天，其余通常 90 天）。明确人工确认的长期内容没有强制自动遗忘日。

主动遗忘删除条目、版本和依赖链，并记录不可逆摘要及原消息片段的位置。原聊天原文仍保留给本人查看；送入后续模型的对应片段被遮蔽，相关旧回答也退出推断。删除同一消息里的一个事实，不阻断该消息另一个未撤销事实的记忆。旧来源、相同正文自动生成和后台回放不能把被遗忘内容带回来；如需重新使用，可以由本人明确手动重新保存。

明确说“请清空我的所有记忆”会清理所有项目下的长期、会话和工作记忆，并建立用户级历史代次界线。尚未被摄取的旧消息也不能被整理历史重新学习。新消息属于新代次，可以正常形成新的记忆。旧遗忘命令不会因历史回放再次删除后来人工确认的内容。

这不是聊天记录删除、磁盘安全擦除或备份抹除；旧离线备份保留创建时的内容。自然语言识别采用保守规则；含糊对象、引述、假设和大量匹配要求本人在记忆工作台核对，不能宣称理解所有表达方式。

## 6. 并发、迁移与恢复

同一对话切换项目会切换工作框架；切回原项目可恢复原框架。全局版本计数用于拒绝过时编辑，实际工作文本按范围独立保存。回答只绑定实际提供的记忆集合；无关条目编辑不再打断生成，实际选中来源、工作条件或权限变化仍让过时结果不能发布。

schema 1/2 经现有初始化迁移到 3。人工内容保留；前版自动写入的疑似临时长期记录标记重新核对，任务来源补经历复核期。已声明 v3 却缺少必要表的数据库拒绝启用，不能悄悄当作完整数据库运行。升级前使用 SQLite backup API，启动后检查完整性、外键、原业务数量和未登录接口权限。

独立 JSON/Markdown 继续用于长期条目的迁移/编辑；外来历史只作为待核对档案，不恢复其他账号的真实权限和来源。完整运行状态（会话片段、工作框架、检查点、复盘、反馈、保留设置与遗忘界线）通过 SQLite 备份恢复。
