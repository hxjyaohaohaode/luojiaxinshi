# 记忆交互与可靠性契约 v7

应用 1.17.0，沿用记忆引擎 schema 6。本文补充 [知识树 v6](MEMORY_TREE_V6.md)，描述日常操作与异常恢复。原话／来源证明、访问权限、跨会话和遗忘规则继续生效；没有新增默认付费后台循环。

## 默认使用流程

打开记忆优先显示可编辑记忆与资料概览，避免长文分片挤满首页。输入关键词时自动覆盖完整资料；展开资料目录时自动展示当前原文片段。用户无需先配置检索类型，可选筛选仍提供全部内容、可编辑记忆、资料原文、状态和更新时间排序。

搜索覆盖正文、标签、项目名称、专题、完整目录路径，以及资料标题和原文位置；多个词可同时限定项目和正文。当前目录包含子目录，也可切换全库。浏览与回答召回相互独立：回答仍先检查账号、项目、附件权限、来源版本及生命周期，移动目录不会扩大使用范围。

会话与工作记忆使用独立搜索词、分页和当前视图。刷新及编辑条件后仍保留该视图；单页 50 条，能到达第 100 条之后的全库记录。临时条件显示所属会话、形成当轮／会话内寿命、保留期限及人工修订状态。继续对话、编辑、长期保留、遗忘和工作记录均有入口。单个会话既有的工作上下文保留上限与全库浏览分页是两项独立限制。

## 编辑、整理和异常恢复

| 场景 | 实现的行为 |
|---|---|
| 切换条目、目录、页面或刷新标签 | 就地正文草稿按账号暂存在当前标签的 `sessionStorage`；保留正文、原始版本与时间，重新打开提示恢复 |
| 退出、会话失效、切换账号 | 清除记忆草稿与内存目录；失效的旧请求不能替后来登录的会话执行登出 |
| 存储被拒绝或容量已满 | 仍可在内存中编辑并向服务端保存；此时不能保证刷新恢复 |
| 草稿与服务端版本不同 | 保留草稿并展示最新正文；用户明确对照后才以新版本继续，不自动覆盖并发修订 |
| 已保存但网络回包丢失 | 相同操作使用同一标识，重试读取持久回执。正文、目录创建／改名／移除、单条及批量移动均覆盖 |
| 大小写或内部空格不同 | 按精确 UTF-8 内容生成操作指纹，不使用事实去重的规范化哈希。旧格式回执不匹配时返回冲突，不擅自重做 |
| AI 修改 | 支持选定部分、整条整理、仅在末尾补充。追加使用零宽字符范围，原有正文逐字保留 |
| 已满 2000 字符仍请求追加 | 调用模型前拒绝，可先精简或另建；返回结果越界时也不写入半截正文 |
| 未展开的深层目录 | 直接搜索全路径，结果分页；不要求预先展开侧栏，同名目录依路径区分 |
| 批量整理 | 多选本页记忆后移动、归档、启用或遗忘；先检查全部版本再原子提交，冲突时不部分修改 |
| 移除自建目录 | 只移除容器；记忆、资料和子目录上移保留，同名子目录加后缀。系统目录不能移除 |
| 改名后再次创建原名称 | 新目录具有独立身份，不复用已改名或移走的旧路径键 |
| 恢复历史版本 | 新增修订，恢复仍属于本账号的历史位置；不隐式重建已删除目录，保留当前暂停或归档状态 |
| 当前目录在其他标签被移除 | 回到全部记忆，清理过时详情，草稿独立保留 |
| 后台形成或修订记忆 | 仅在页面可见时检查不含正文的变更令牌；打开详情、目录选择、编辑、弹窗和批量操作期间只提示变化，关闭详情后同步待更新内容 |
| 断网、读取失败、旧搜索迟到 | 保留已有内容和输入，提供重试；取消或丢弃过时请求，不覆盖新查询 |

最多暂存 20 个条目的草稿，载入时清理超过 7 天的旧草稿。浏览器清理会话存储或销毁标签会影响恢复；这是临时编辑恢复，不是服务端备份，也不是永久遗忘的撤销功能。

只有结果未确认的请求继续复用同一标识；确认成功后，新操作获得新标识。这样既防止网络重试重复写入，也允许用户遗忘后明确重新保存同样的人工内容，不会被旧创建回执一直拦住。

项目默认由 Agent 依据明确原话建立和选择。“自动维护与设置 → 项目管理”提供名称、说明、新建和删除入口，不要求普通对话先手动建项目。条目可以直接打开所在目录，或调整记忆层级及跨会话范围。

## 来源和质量检查

`source-sync` 只重建资料索引，不能把来源摘录改写成整份资料的概览；同步记录当前来源版本。人工正文不被后台覆盖。来源级遗忘不仅阻止后续作业和全文分片，还使其他尚存的同源摘录失效；直接片段接口也检查阻断，来源同步不能撤销遗忘。

遗忘前会说明关联资料或任务的自动记忆也会停止；原资料、聊天和离线备份保留各自生命周期。没有声称实现任意语义重写后的同义事实遗忘。

Agent 的目录提示按问题与完整路径相关性选择，避免只取前 24 个目录。项目、专题和路径共用有界预算，深层路径不能挤掉所有相关项目。目录只是线索，事实仍经权限和版本检查后提供。

只移动目录或移除目录容器时，只有完整连续的 `user-placement`／`user-folder-removed` 修订链、且事实与范围一致，才允许继续使用旧回答。正文、范围、停用或遗忘发生改变后仍撤销其后续上下文用途。快照 v2 对字典键排序后计算指纹，避免集合与查询返回顺序不同被误认为事实变化；已有 v1 快照仍按旧协议核对。

发送给模型的记忆正文、标签、目录／项目／专题提示、工作上下文和来源片段统一过滤已识别的凭证模式；不改写用户保存的原件。凭证在完整原段上识别，再遮盖每个重叠分片，防止长令牌或 PEM 私钥跨片后失去前缀而漏出。升级时旧分片立即失效，再通过一次持久作业自动重建。这里覆盖已实现的识别模式，不是对任意编码、混淆或所有敏感信息的检测保证，也不声称追溯清除已经存在于原聊天或文件中的内容。

Agent 目录提示同时排除空路径和已遗忘／删除的资料节点及其子路径，避免已停止使用的来源通过文件标题再次进入模型。人工目录仍可在浏览器管理；提示筛选不会删除目录或改变其中条目的访问范围。

“可按需调用”表示可成为候选，不代表每轮已经采用。实际采用回执、来源与历史单独记录；全局暂停时列表显示暂停调用。侧栏计数包含子目录，旧来源／阻断片段不计作当前全文；生命周期统计来自本账号真实记录。

## 与参考记忆项目的关系

13 个固定版本的全文件清单、SHA／CRC 及逐项目取舍继续见 [v6 来源复核](verification/memory-upstream-v6.json) 和 [v6 设计](MEMORY_TREE_V6.md)。本轮没有把既有扫描声称为新一轮逐行审读，也没有用“融合百分比”代替证据。

| 既有参考机制 | 本轮进一步落地 |
|---|---|
| OpenViking 的 L0／L1／L2 逐步载入，仅作设计参考 | 首页不展开全部原文；检索和进入资料时自动展开，层级同时服务实际界面 |
| memU 的宿主 Agent 维护、LangMem 的结构化操作 | 继续自动选用和写入，补齐精确追加、相关目录提示与来源身份限制，不增加默认付费审核 |
| EverOS 的增量协调与可恢复变更思想 | 无正文的变更令牌、空闲同步、精确指纹、持久回执、整批版本检查与原子移动 |
| Letta 的可编辑上下文、LangGraph 的状态分离 | 会话编辑与浏览状态独立，草稿恢复、并发对照和字符范围保护落实到界面 |

这是机制适配，不表示移植 SDK、专有组件、向量数据库或知识图谱执行系统。检索仍使用既有中文全文、结构化范围和模型查询规划，不是任意语义问题的准确率保证。
