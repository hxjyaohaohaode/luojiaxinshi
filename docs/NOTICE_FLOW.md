# 通知接入与办理契约 · 1.21

本次范围是现有上传、粘贴和链接入口，以及资料、行动、跟进、提醒和日历之间的衔接。未接入微信、QQ 或校园账号，不把来源目录视为已经接通的渠道。

## 检查结论与对应改动

| 链路 | 原有问题 | 当前行为 | 主要实现 |
|---|---|---|---|
| 原文进入系统 | 地址仅保存为元数据，不读取正文 | 主动读取公开链接，先核对预览，保存同一份内容快照，保留原文地址和读取时间 | `app/notice_intake.py`、`static/notice-intake.js` |
| 多则群通知 | 一次只能围绕一则通知，混合事项容易堆在一起 | 最多 12 个独立收件项，各自有标题、正文、附件、来源、提交标识及保存结果；由用户明确拆分 | `static/notice-intake.js` |
| 后续材料 | 新通知与原事项补充没有统一选择 | 每项可新建或补充已有通知；补充保留原件并重新进入待处理，正式要求仍需核对后更新 | `app/main.py`、`static/notice-intake.js` |
| 纯告知 | 必须产生待办才能离开待处理清单 | 可记录“仅存资料”“与我无关”“已结束”，可重新处理；存在待办时先处理待办，避免隐藏未完成事项 | `app/notice_intake.py`、`static/library.js`、`app/insights.py` |
| 办理方式 | 所有事项都围绕材料申报进度 | 支持一般行动、申报、参加活动、阅读、选择、领取、缴费核对、等待结果及自定义办理；仅记录本人实际进展，不代缴费或提交 | `app/workflow.py`、`static/workflow-kinds.js` |
| 前置关系 | 条件和步骤均要求全部满足 | 支持全部或其中一项；取消、删除、待复核步骤不计为完成；可选参与意愿仍独立校验 | `app/action_plans.py`、`app/workflow.py`、`app/action_review.py` |
| 个性化过程 | 缺少每件事自己的执行清单 | 最多 20 个自定义步骤，可记录完成和说明；改名清除原完成勾选；保存并完成使用原待办事务及复核规则 | `app/workflow.py`、`static/workflow-kinds.js` |
| 时间含义 | 活动发生时间容易被当成截止时间 | `scheduled` 保存活动或办理时段，与截止日期、个人计划分开；允许未知结束时间；日历按真实区间导出 | `app/models.py`、`app/ai.py`、`app/calendar_export.py`、`static/notice-timing.js` |
| 跨页面状态 | 知悉资料与无截止活动仍进入未处理或未知期限计数 | 资料列表、工作台、提醒、日期筛选与日历使用对应的处理状态和时间含义 | `static/overview.js`、`static/calendar-model.js`、`app/insights.py` |
| 重试与迁移 | 未知保存结果容易重复创建，新增字段可能在导入时丢失 | 提交回执按账号和请求标识去重；重复材料明确复用或另建批次；迁移保留流程和出处，但时间与外部条件需重新核实 | `app/notice_intake.py`、`app/data_transfer.py` |

账号设置、政策阅读入口、提醒已读管理、聊天工具执行、记忆、个人日程、导入导出、备份、模型证据与语义复核一并纳入回归。原有同意记录保留；政策仍通过登录页和账号页的文字链接阅读，不恢复登录后强制弹窗。未重写聊天和记忆架构。

## 界面与点击边界

- 页面、侧栏、卡片、弹窗和通知预览统一纯白；分区、边框和遮罩使用中性色，保留品牌操作与状态强调。
- 内容分组最多一层可见外框：去掉看板列、结果面板、原文与草稿、办理分组和记忆布局的重复边界；内部以留白或单线分隔。待办按实际容器宽度切为单列，手机表单与批量入口减少重复内边距，保留输入控件和键盘焦点。
- 通知资料、完成记录、单一目的来源卡使用整卡原生链接，支持留白点击及键盘 Enter；不嵌套第二个链接或按钮。
- 待办标题、时间和状态构成办理主按钮；完成勾选、原通知、附件、编辑和日历导出各自独立，正文拖选不触发办理。
- 批量保存结果的主区域打开通知，移出操作独立；记忆批选和最近对话扩大实际点击区，使用布局占位避免覆盖邻居。
- 工作台日期、聊天与记忆条目、日历事件、设置项、提醒管理和表单按各自原生控件检查；多操作信息区不增加父级跳转。
- `scripts/navigation_target_checks.mjs` 与通知流程套件覆盖桌面、手机、留白点击、键盘进入以及子操作边界；不把单一导航规则扩展到整个日历网格或编辑表单。
- 设置页按个人资料、账号服务、显示与声音分组，同一时间只显示一个分组；个人条件按身份、学期、联系、目标编辑，默认仅四个身份字段，保存仍包含全部字段。
- 弹窗先显示外壳，再以短间隔显示可见内容组；快速关闭或重开会取消旧动画，系统减少动态效果和页面关闭动效设置均有效。
- 引用摘要、记录摘录和完整材料预览共用 `static/record-preview.js`。待办、个人条件、记忆、日历查询与操作回执显示中文信息，隐藏系统字段和记录定位标识；用户上传的普通 JSON 原件保持原文。

## 数据看板与刷新

`GET /api/insights` 按本人实际记录生成通知流转、材料接入、事项状态、期限及跟进维度，并返回各指标对应的记录集合。趋势和期限图同样带对应事项标识，点击图表进入精确筛选结果，可清空筛选回到全部记录。完成趋势排除已删除及非本人范围事项；修改已完成事项的备注不会把完成时间改到今天；未确认期限不当作已核实逾期。

看板采用核心数字、完成趋势、期限堆叠柱、状态环图和通知处理条形图。保存相关数据后、重新进入窗口及前台定期刷新时重新读取；未变的数据只更新时间，不重建点击目标。刷新失败保留上次结果并可重试。延迟刷新捕获原页面标识，请求开始与返回时均检查路由和账号，避免切到设置等页面后被旧响应覆盖。

记忆索引未就绪时会更及时检查更新；先读取索引水位再读取条目，避免把尚未显示的条目误判为已同步。正在编辑或选择时继续保留用户操作。

## 接入边界

- `POST /api/intake/link` 只读取公开 HTTP(S) 页面或支持的附件，禁止内网目标及跳转。DNS 地址固定到实际连接；整体最多 20 秒、最多 4 次请求；HTML 最多 1.5 MB，其余原件最多 5 MB。正文超过 10,000 字直接报错，不静默截断。
- 不自动登录，不使用个人平台 Cookie，不递归下载网页附件，不读取网页内的图片和音视频。预览列出外链附件和媒体提示，由用户补上传关键原件。
- 预览属于当前账号，一小时内有效；每小时最多 20 次读取、最多保留 12 份未过期预览。保存后重试仍可使用有效预览；过期数据在下次读取或启动时清理，备份恢复不恢复临时预览。
- 上传、粘贴和链接可组合为一则通知；总文字、原件数量、账号配额仍由原接口检查。批量操作逐项事务保存，失败不撤销已成功项。刷新后原件文件需重新选择，已保存项有实际通知链接。
- `PUT /api/notices/{id}/disposition` 与补充接口使用版本检查。链接预览及读取结果不会直接生成、完成或提交待办；AI 草稿仍需本人确认。

## 时间与流程数据

`TaskData.scheduled` 为可空对象：`kind` 是 `event` 或 `window`；包含开始/结束日期与时刻、`confirmed` 和原文依据。结束未知就保持空，不能默认增加时长。模型不能替本人确认。日历导出活动区间与报名截止为不同稳定 UID；同一显式提醒只产生一个闹铃。

工作流保存 `execution_mode`、`phase_label`、`milestones`、`dependency_mode`、`condition_mode`。旧记录默认保持材料申报及全部满足规则。自定义名称是显示进展，实际完成仍由待办状态及服务端校验决定。未选择的另一条路径可保留待复核记录，不阻止已经核实的可选路径继续；不存在可用路径时不能完成。

数据库新增 `notice_intake_schema_version=1`；工作流版本从 2 升为 3。升级仅增加表和字段默认值，不移除旧记录。升级前备份；旧版拒绝读取新工作流版本，回退须恢复升级前备份，不能直接把新数据库交给旧程序。

## 验证与仍需真实场景确认的部分

- `tests/test_notice_intake.py`：公开链接解析、原文快照、隔离、过期、地址边界、幂等重试、资料处理与补充。
- `tests/test_flexible_workflow.py`：不同办理模式、全部/任选前置和条件、参与意愿、清单变更、实际完成与历史复核。
- `tests/test_notice_timing.py`：时段依据、未知结束、跨天与全天日历、截止和活动分离、提醒及迁移。
- `tests/notice-intake.test.mjs`、`tests/notice-timing.test.mjs`：状态投影、日历投影、工作台计数与不变的原始数据。
- `scripts/verify_notice_flow.mjs`：三种浏览器通过真实本地接口执行上传/粘贴、链接预览、纯资料处理、活动核对、完成清单、批量部分成功及补充，并检查桌面、手机、横屏布局。链接提供方是明确标识的合成夹具；网络安全与真实解析器在 Python 测试中独立验证。
- `tests/test_insight_data.py`、`scripts/insight_data_checks.mjs`：统计范围、完成时间、指标与列表一致、手动及数据更新刷新、焦点保留、延迟刷新跨路由隔离。
- `tests/record-preview.test.mjs`、`scripts/record_preview_checks.mjs`：真实查询及回执形状的可读展示、完整预览与摘要一致、普通上传 JSON 不被误改写。
- 视觉套件另检查索引从排队到就绪后无需手动刷新即可显示记录，使用真实本地索引与合成数据，不调用外部模型。

这些是工程验收，不是实际学生使用研究、全站网页兼容性或模型准确率证明。真实学校的动态网页、登录页面、特殊表格、模糊图片和不完整年份仍可能需要补充原文并人工核对。新增办理模式和时段提取尚无新的真实 MiMo 场景准确率统计。外部渠道接入留待下一阶段逐一核实接口、授权和实际消息样本。
