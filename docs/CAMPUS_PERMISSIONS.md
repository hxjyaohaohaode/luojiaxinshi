# 学院身份与定向通知

本功能为武汉大学资源与环境科学学院提供学院角色、定向发布与接收。学院角色由管理者单独授权，不由用户自行填写的个人资料决定；已有账号默认不会自动成为学院成员。

| 身份 | 可以做什么 | 权限边界 |
|---|---|---|
| 系统管理员 | 指定或移除学院管理员，也可维护学院成员 | 发布学院通知仍须另有学院管理员或辅导员身份；不能读取其他人的私人通知、待办、聊天或附件 |
| 学院管理员 | 管理本院辅导员与学生，向全院、指定年级或指定班级发布；管理本院发布记录 | 不能任免学院管理员或管理其他学院；只能看到送达数量，不能查看个人办理状态 |
| 辅导员 | 查看自己负责范围内的学生组织信息；向已授权的范围发布、修改、撤回和补发本人通知 | 全院或全年级权限须明确授予；不能修改成员身份或查看个人数据 |
| 学生 | 接收与本人学院、年级和班级相符的通知，按原有流程核对并处理 | 不能发布学院通知或查看其他成员名单；个人通知、任务和资料归本人所有 |

系统管理员和学院管理员是两层独立权限。预设学院为 `sres`（武汉大学资源与环境科学学院），当前界面不提供新增其他学院的功能。一个账号同时只有一个学院身份，变更身份和范围立即影响后续授权。

## 开始使用

1. 用户先注册账号。初次部署且没有系统管理员时，启动脚本在数据目录生成 `admin-setup.url.txt`；管理员本人使用其中的一次性链接设置系统管理员账号及密码。该链接只交给可信管理员，不要公开。已有管理员时无需重新初始化。
2. 系统管理员进入“学院工作台”，按已注册账号名授予学院管理员身份。请在线下或通过机构认可的方式先核实真实身份。
3. 学院管理员在“学院工作台”按账号名设置辅导员、学生。学生填写年级与班级，例如 `2026级` 和 `1班`；辅导员每行填写一个负责范围，如 `2026级 / 1班`、`2026级` 或明确填写 `全院`。年级和班级采用完全一致的文字匹配，请事先统一命名。
4. 学院管理员或已授权辅导员选择全院、年级或班级，年级和班级可参考已有名称；填写标题、正文及可选附件后，点击“核对并发布”，确认学生与工作人员人数。如果核对后接收成员发生变化，系统会要求重新核对。发布后可在记录中更正、撤回、重试未送达，或向后来加入范围的成员补发。补发也会重试当前范围内尚未送达的记录。
5. 学生在“我的通知”中收到自己的独立副本，需自行核对后再整理为个人待办；发布者只能看到汇总的站内收件情况，收件不代表已读。接收范围除符合条件的学生外，也包含学院管理员及负责该范围的辅导员，人员统计会区分学生与工作人员。新通知会标明来自学院工作台，并在长度允许时显示接收范围。

发布记录可按标题、发布人、年级和班级搜索并分页，仍只显示本人有权管理的记录。每条通知最多 3 份附件，单份 5 MB、合计 8 MB；正文和附件提取文字合计不超过 10,000 字，单次接收人数最多 1,000 人且附件副本总量最多 50 MB。超过限制时请按班级分批发布或缩减附件。发布表单在同一页面会话内切换页面可保留文字，重新进入时须重新选择附件；刷新页面不会恢复该发布草稿。

## 范围变化、私有数据与恢复

已核对学院身份的学生可以从个人待办发起一项站内协作，选择覆盖本人范围的辅导员或学院管理员。接收人看到的是本人明确分享的事项标题、说明及所选材料版本，可以接收、退回补件和保存办结回执。发起人可以补交或撤回。每次操作保存独立回执并检查版本，原个人待办和校方受理状态各自记录。系统管理员的身份本身不授予读取协作内容的权限。接收范围撤销后停止访问原协作和附件，发起人仍可查看回执。材料被删除或协作被撤回后，原下载链接也按权限失效。

- 发布时保存当时的接收成员；后来加入的成员不会自动接收历史通知，可由有权限的发布者主动补发。补发仅覆盖目前符合该通知范围的成员，重复补发不会生成重复副本。
- 成员换班、移除授权后，不再接收原范围内的后续更正或撤回；已经接收的个人副本、待办和办理记录保留。更正和撤回只发给原接收成员中目前仍符合范围者，个人待办不会被自动删除或覆盖，需由本人核对。
- 学院管理员能查看本院组织名单和学院通知正文；辅导员只能看负责范围内的学生组织名单和本人有权管理的发布记录。发布记录显示数量，不包含个人办理状态。系统或服务器维护人员若能直接访问数据库或备份，仍须通过部署环境的权限管理和保密制度约束。
- 数据库完整备份包含学院成员授权、通知与个人数据，须限制访问。使用恢复工具时会清除学院身份和辅导员范围，避免旧备份恢复已撤销的授权；学院及通知记录、个人数据保留。恢复后由系统管理员重新授予学院管理员，再由学院管理员重新核实并授予成员权限。
- 本系统的账号注册与学院授权不等于武汉大学统一身份认证，尚未对接学校单点登录或学籍数据。正式使用前需要学院确认管理员、辅导员、学生及其对应范围，并按实际部署需求配置受邀注册、HTTPS、备份访问和运维权限。

接口权限和数据隔离的自动测试使用虚构账号与独立数据库：`tests/test_campus_permissions.py`。本地演示脚本 `scripts/campus_preview_server.py` 仅使用合成账号、独立数据目录及 `localhost` 地址，不代表真实学院身份或真实用户验收；不要改成正式站点的 `127.0.0.1` 地址，以免两个服务的登录状态相互覆盖。
