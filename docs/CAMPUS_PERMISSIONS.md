# 学院身份、定向发布与协作边界

学院身份由管理者明确授权，个人资料中的学院、年级或“教师”标签不授予组织权限。本系统账号与授权也不等于武汉大学统一身份认证，未建立的学校单点登录、学籍查询或校方办理接口不能被界面模拟为已接通。

## 身份与职责

| 身份 | 可以做什么 | 权限边界 |
|---|---|---|
| 系统管理员 | 指定、移除学院管理员，维护学院成员 | 发布仍须另有学院管理员或辅导员身份；不能读取他人的私人通知、待办、聊天或附件 |
| 学院管理员 | 管理本院辅导员、学生；向全院、年级或班级发布；管理本院正式发布及组织审计 | 不能任免学院管理员或管理其他学院；个人办理进度不成为管理看板 |
| 辅导员 | 查看自己负责范围内的学生组织信息；在明确授权范围内发布，并管理本人且目前仍有权限的发布记录 | 全院或全年级权限须明确授予；不能修改成员身份或查看未分享的私人数据 |
| 学生 | 接收符合本人授权学院、年级与班级的通知；整理自己的待办；按需分享明确选定的事项和材料版本 | 不能发布学院通知、查看组织名单或访问其他人的私有资料 |

系统管理员与学院身份是两层权限。预设学院为 `sres`（武汉大学资源与环境科学学院），当前界面不提供新增其他学院。一个账号只有一个学院身份，变更与撤销立即影响后续读写和后台执行。没有明确的学校毕业、离院或任职到期规则时，由管理者核实后变更或移除当前授权，系统不根据自填年级推测权限期限。

## 成员录入与名称迁移

1. 成员先注册账号，管理者通过机构认可的方式核实身份。初次部署的系统管理员通过数据目录中的一次性初始化链接设置账号；已有管理员时不重新初始化。
2. 系统管理员授予学院管理员；学院管理员授予本院辅导员和学生。学生须填写年级、班级，辅导员须明确负责范围，例如 `2026级 / 一班`、`2026级`，或明确的 `全院`。
3. 批量录入支持带表头的表格文本、CSV、JSON，每批最多500行。先预检账号、重复项、现有归属、角色与范围权限，再明确勾选要提交的无错行。预检本身不修改权限。
4. 名称检查只进行无歧义的规范化，例如将 `2026` 规范为 `2026级`，统一全半角与空白。`一年级` 不会被猜成某个入学年份；同名班级仍按所属年级区分。空值、格式错误和跨院冲突逐行说明。
5. 预览显示变更前后身份，以及已有正式发布范围将新增或移出的接收者。已发布的范围文字不会随名称迁移被悄悄重写；个人旧通知也不会删除。管理者应据实际影响选择本次迁移的行。

预检有效期10分钟。提交时重新检查操作者和目标成员的完整授权快照；冲突返回409，旧预览不会覆盖新授权。同一预检、相同行集合的重放只返回原结果，不重复授权。名称迁移和入班不自动补发历史公告、不自动开启收费整理。

## 草稿、受众核对与正式发布

发布草稿独立保存在本人账号，可包含尚未选定的范围和未完成正文。原附件与解析状态随草稿保存，支持离开、刷新和另一设备恢复；网络失败明确显示“未保存”，多端冲突保留当前输入并要求核对。每人最多50份草稿。草稿不分发、不提醒、不计入已发布记录；成功发布后删除本次使用的草稿。

正式发布必须先核对具体范围及学生、工作人员人数。复核凭据绑定当前发布人的完整身份、范围，以及全部接收者的账号、角色和授权版本；缺失、过期、服务重启或成员变更均须重新核对。人数相同但成员换人也会失效。零学生单独提示，工作人员收件不能代表学生已收到。服务器强制执行这道核对，不能省略字段绕过。

每条公告限制为最多3份附件、单份5 MiB、总计8 MiB；正文与附件提取文字合计最多10,000字，单次接收者最多1,000人。发布原件与草稿另受部署配置的存储容量限制。原来的“附件字节数乘人数不得超过50 MiB”限制已移除：每个正式版本保留不可变原件，各收件人通过本人通知上的授权引用访问，不再为每个人复制一份二进制内容。个人容量按本人收到的逻辑原件大小计算，不会因为共享存储而绕过容量。

正式发布先持久保存逐人的分发任务，一次请求最多处理24人，其余由后台继续执行。每人使用短事务，失败记录单独保留；重启可以继续，已成功的人不会重复收件。执行每个人的任务时重新验证当前发布管理授权、版本和接收范围。授权失效时明确失败，交由当前有权管理者核对恢复。发布请求的幂等编号可恢复丢失的响应，但相同编号配不同内容会冲突。

## 更正、撤回、恢复与历史补发

- 正文、附件、发布有效期和历史参考标记属于正式版本。更正保留旧版本，显示标题、正文和附件增删摘要；管理者可下载自己当前有权管理的历史原件。接收人的旧材料与个人办理进度保留。同内容附件改名会更新当前名称并保存改名前后记录，原件引用和引用它的个人证据保持。
- 撤回产生新的撤回版本及说明，原发布历史保留。正式恢复只能从当前撤回版本发起，必须填写实际恢复说明，产生新的正式版本；不会自动重新打开个人已取消或已完成的任务。
- 以旧内容更正会复制选定版本的正文、原件及有效期政策，产生新版本并记录目标版本与原因；不修改已有审计历史，也不能用内容回滚绕过正式恢复。
- 发布者可以显式设置带时区的有效期或“仅作历史参考”。未设置时显示“未设置有效期”，不从正文猜测截止。更正时省略政策字段则保留既有值；显式清空可移除有效期。
- 补发必须重新核对当前正式版本和具体受众。只增加当前合法且尚未收到的成员，已收者不重复，撤回公告禁止补发；后台仍逐人核对权限。
- 已超过发布方标注有效期、或被标为历史参考的版本，须明确确认“作为历史参考”才能补发。站内可查原文，外部收件及该通知派生的催办提醒被抑制，不自动创建或重启个人任务。

换班、撤权、离院后，个人已经收到的通知、原件、任务和办理历史保留，旧范围的私密新内容不会继续开放。正式更正、撤回、恢复只交付原接收者中目前仍符合该发布范围的人；新授范围不自动开放旧范围。需要跨负责人交接具体事项时，由当事人重新确认当前授权接收人及分享材料，不能借历史事项恢复整班或整院的访问权。

## 分发、渠道接受与阅读证据

发布记录首先显示站内分发的已送达、待处理、失败和不再属于范围数量。站内送达只表示记录已经进入对方账号，不表示本人打开、设备展示或办理完成。

发布详情还按浏览器推送、邮件分别统计最近30天现存台账中能够明确关联到本公告收件记录的事件。展示供应商接受次数及涉及的不同账号数量，并区分等待、执行、失败、取消和提交未确认等状态。同一人的多个设备可以形成多次记录；没有明确收件引用的旧台账不被猜测关联。

本人打开和发布级显式回执目前显示“未知”，不通过页面轮询、后台下载或个人待办完成状态推断。统计不返回个人邮箱、设备地址、私有待办、材料或办理完成率。0只表示没有当前可查询的关联证据，不证明此前从未发送。

## 协作与本人跟进

已核实学院身份的学生可从个人待办发起协作，选择覆盖本人当前范围的辅导员或学院管理员，明确分享事项标题、此次说明和勾选的材料版本。协作可接收、拒收／不再负责、要求补件、补交、保存办结回执和撤回。各操作检查双方身份、当前范围和协作版本，并保存独立回执；校方受理状态和个人任务状态不因此被伪造为完成。

转交另一位负责人由原发起人重新选择当前有权接收的对象、具体说明及材料版本。旧协作关闭文件分享并保留历史，新负责人不会自动获得旧聊天、旧备注或未重新勾选的附件。协作及其材料的所有读写都会重新验证权限；撤回、拒收、撤权或删除材料后，旧下载链接按相应边界失效。

协作双方可分别设置**只属于自己**的跟进时间，修改和取消使用独立版本，互不影响，也不更改原待办或校方截止。到期后进入本人提醒，按本人渠道与免打扰偏好重新计算；未到期的计划可在协作详情查看。协作关闭、双方当前授权失效或账号注销后停止跟进，不把“超时”写成学校拒绝或逾期办理。

## 账号注销和恢复

注销前展示个人通知、待办、对话、安排和草稿的删除数量，以及将为对方保留的协作回执数量。注销时关闭原协作和全部共享文件链接，只为仍有权限的对方保留参与事项的必要动作、时间和对方自己写的说明。已注销身份显示“已注销账号”；其私人说明、文件名、文件访问和具体身份不复制到留存回执。学生保留自己的事项标题与原个人材料；受理方得到匿名的最小回执，其后每次访问仍重新核对职责范围。

已向他人正式发布的公告及其不可变原件继续支持他人已有的授权引用，发布者显示为“已注销发布者”。发布者注销不应使他人已经收到的正式材料突然丢失，也不授予任何新的访问权。完整数据库备份中的旧数据按部署的备份保留周期轮换。

完整备份包含私有数据，须限制访问。恢复工具清除旧会话、学院身份和负责范围，清除未提交受众核对及分发授权，并暂停未完成分发。恢复后须重新核实并授予成员权限；管理者必须重新核对当前受众后才能重试分发，单纯重启后台不能恢复旧授权。本人草稿、原发布版本、旧个人记录保留。正常服务重启也会作废尚未提交的受众复核与成员预检，但不会删除草稿或已提交幂等回执。
