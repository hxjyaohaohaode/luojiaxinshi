# ADR-005：通知处理的真实进度、执行存活与延迟测量

日期：2026-10-18。实现版本：1.8.1。状态：采用。

## 问题与证据

1.8.0 的真实赛事材料成功请求耗时 187.578 秒。此前通知接口缓冲完整 JSON，无法区分等待模型与本地校验；界面又用 `AI_TIMEOUT_SECONDS + 30` 判断中断，而该设置是 HTTP 读取无数据的超时，并不是总耗时。活着的长请求可能被显示为失败并允许重复提交。

使用相同来源和合成个人条件，对 Pro 的开启思考／关闭思考进行一次成对诊断。关闭思考用时 40.109 秒，但后续按原有业务要求复查发现遗漏推荐咨询，不能作为正式默认路径；开启思考约 175.688 秒，首段答案到达为 100.141 秒，最终一项任务缺少依据而被拒绝。后续六类合成通知的十二次成对调用中，两种模式各有一个可选事项案例未通过既定检查。这些观察说明直接关闭思考不能满足质量要求；不是独立参与者、总体准确率、吞吐或 P95 结果，也不能证明模型服务稳定提速。

报告分别保存在 `artifacts/mvp-acceptance/notice-speed-business-20261018.json`、`notice-speed-business-semantic-audit.json`、`notice-speed-synthetic-20261018-v2.json`。前一报告的初始基础检查不足，补充语义审查单独保存，未覆盖原始结果。

## 决策

- 保留当前 Pro 思考模式、一次正式生成调用和人工确认。不给失败结果自动补写来源，不自动重试计费请求，不默认为用户切换更贵模型。
- 使用供应商支持的 SSE 接收同一次请求。收齐 `finish_reason` 与结束标志、解析完整 JSON，再执行原有事实、精确引用、日期和办理依赖校验；半段 JSON 不展示为草稿。兼容返回完整 JSON 的接口，但不为这种响应伪造首段等待时间。
- `notice_stream.py` 对整条流、单事件及答案内容设置大小上限，处理分段 UTF-8、CRLF、保活消息、用量尾包、截断及供应商错误。任何失败只留下当前已返回的合法数值用量。模型思考正文不累计、不落库、不送到前端。
- `notice_progress.py` 只持有白名单标量诊断；真实阶段是整理、接收、校验。新只读状态接口不返回原文附件，前端约每三秒查询，后台标签暂停查询，失败退避，换页或退出后忽略迟到响应。最终仍由原生成接口及版本检查决定是否采纳结果。
- 用执行记录状态与进程租约判定是否运行；只有没有执行记录的旧数据才用原时间阈值回退。读取、首次提交检查及写入事务复查采用同一判定。
- 提供给模型的结构声明明确要求任务责任主体、非空原文依据、办理分类、前置序号和条件；八类事实逐项声明字段。提示强调自愿活动及其报名环节保持可选，外部确认限制绑定参加步骤。手工编辑和已有记录的兼容结构不变。

MiMo 的 JSON 模式只保证 JSON 语法，不强制执行提示中的 Schema；官方也要求先拼接完整流再解析。因此仍保留服务器校验与人工核对，不能把更详细的提示视为语义正确性保证。[官方结构化输出说明](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/text-generation/structured-output)

## 持久化与回退

`execution_schema_version` 从 1 升到 2，增加按执行 ID 关联的 `execution_metrics`；执行、通知或账号删除后相应诊断随外键删除。只通过白名单保存／返回有限非负数值。旧库升级不重写已有执行，旧备份恢复后迁移到新结构。回退旧程序需恢复升级前备份到新目录，不能直接用旧代码打开新库。

通知与对话共享已有执行登记、租约和终态；通知协议读取和标量测量独立于业务确认，未来可替换供应商或统计观测。没有增加外部遥测、数据库服务或运行依赖。

## 验证与限制

回归覆盖完整流、缺结束标志、截断、错误包、错引用、用量保留、大小上限、隐私字段过滤、账号隔离及旧执行库迁移。浏览器检查长任务存活、真实阶段变化、完成自动刷新、退出／换页竞态和多尺寸处理记录。实际通过数量及真实供应商复验记录见 [TESTING.md](../TESTING.md)。

流式接收和阶段反馈改善可观察性与处理中体验，不等于供应商计算变快。当前没有质量已获验证的全局快速替代路径，也没有证明复杂通知满足目标响应时间。处理超时仍按读取无数据设置，输出预算和流大小有界；本版本没有新增请求总墙钟超时承诺。
