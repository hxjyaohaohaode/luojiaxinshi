# 记忆可靠性与人工管理 v4

日期：2026-10-21。记忆引擎 schema：4。在 [生命周期 v3](MEMORY_LIFECYCLE_V3.md) 的形成、分层、检索和遗忘机制上，补齐版本证据、写入重试、人工修订、复盘作业和管理界面。当轮最终验证数据见 git 历史，当前测试体系见 [验收记录](../TESTING.md)。

## 1. 本轮解决的问题

| 触发情形 | v4 行为 |
| --- | --- |
| 旧回答使用第 1 版记忆，用户已经改成第 2 版 | 展示回答当时看到的正文及版本，禁止用这次旧回答给新版投票；新版的反馈计数重新积累 |
| 编辑或恢复一条已归档、冷却或停用的记录 | 保留原来的使用状态；只有明确勾选重新启用或执行启用操作才恢复调用 |
| 写请求已提交，但浏览器没收到响应 | 新增、修改、删除和批量操作携带操作标识；同一账号、同一操作、同一内容重试读取原回执，避免重复写入 |
| 另一窗口先修改了选中的部分记忆 | 整批版本校验失败、整批回滚，不只修改其中一部分；界面保留编辑草稿 |
| 给来源记录加标签、置顶或锁定 | 事实内容没有变化时，派生依据仍可核对；正文、类型、范围、同类键或有效期变化时重新检查依赖 |
| 更具体的项目记忆已冷却，或只适用于另一个场景 | 先排除不可用覆盖项，再选择通用/专题/项目的有效值，避免无效项目项挡住正常通用默认值 |
| 派生概览没有填写场景，但父记录仅适用于论文 | 继承父记录的实际限制；概览不能绕过来源的场景、权限、有效期和状态 |
| 人工锁住了工作记录，同时新增本会话条件 | 独立的会话条件仍进入模型上下文；人工工作记录不被自动覆盖 |
| 遗忘的记忆曾被其他对话的回答使用 | 删除前撤销相关回答的后续记忆用途；原聊天可查看，但不继续把旧助手正文当作当前记忆依据 |
| 遗忘语句与保存内容只差“记住，”和末尾标点 | 在保守的完整事实匹配中规范化这些捕获包装；不靠模糊相似度删除其他记忆，未匹配会返回未完成回执 |
| 复盘额度耗尽、服务中断、迟到响应 | 额度不足延期；中断不自动再次请求付费模型；迟到的旧执行令牌不能写入新提议 |

## 2. 写入、版本与来源

写入回执表只保存操作名、内容哈希、条目 ID、版本及结果元数据，不缓存记忆正文。服务端保留 7 天、每账号最多 10,000 个回执。浏览器只在当前页面内保留最多 250 个哈希与随机操作标识，切账号立即隔离。相同标识对应不同内容返回 409；条目后来已经遗忘，重放旧创建回执返回 410，不重新创建它。

界面中的上述记忆写操作在 25 秒仍无确认时允许退出等待，并明确提示结果未知。中止浏览器等待不代表服务器回滚；重试沿用原操作标识，重新载入也可以核对当前版本。编辑、删除和批量操作仍有版本校验，幂等回执不能代替并发检查。项目、设置、导入等原有接口保留各自的版本或去重机制，没有把它们一律称为已接入这套回执。

来源检查区分事实变化与管理变化。对于父记忆的历史版本，比较 `content / kind / scope / project_id / topic / semantic_key / valid_from / expires_at`。标签、置顶和锁定变化不改写事实证据；状态、跨会话共享、来源权限和场景仍按当前条件检查。不能因为正文相同就绕过归档、撤销或作用范围。

来源详情逐条展示证据实际所属的对话。办理来源区分可核对、版本已变化、已不可用。父记忆关联展示形成时的历史正文及来源版本，并另标当前版本；不把当前正文冒充历史依据。导入文件内的来源声明继续作为档案显示，不变成本机可验证来源。

反馈同时绑定回答 ID、记忆 ID 和实际提供的版本。修改后旧票不进入新版分数，避免历史好评把刚改错的内容推高。曝光、Agent 报告采用和本人评价仍是三类记录，曝光本身不是内容正确的证明。

## 3. 会话条件、工作记录与遗忘

会话暂存支持直接编辑正文及“仅本轮/本会话内”时长。修订存入独立表，形成时的原话不变；用 `edit_version` 校验并发。人工编辑的片段退出自动晋升，长期保存须本人再次确认。晋升表单默认使用修订后的正文，提交时同时核对片段版本，不能用旧窗口晋升后来已经改过的条件。

模型上下文分开提供人工工作记录和当前会话状态。长期记忆继续最多 12 条、8,000 UTF-8 字节；工作正文最多约 6,000 字节；独立会话状态最多 5,000 字节，目标和当前请求各最多 900 字节。会话状态优先保留本轮条件，自动省略凭证。完整来源历史和管理审计不随每轮发给模型。

记录会话事实、目标、当前请求及检查点来源的曝光关联。删除相关片段时，依赖回答的后续记忆用途一并撤销。遗忘会清理短期编辑覆盖、检查点及派生内容，并保留防旧来源重新学习的边界。归档、停用和遗忘仍有不同含义：前两者保留可管理的内容，遗忘删除在线记忆及其版本/依赖。原聊天和已存在的离线备份须分别管理。

批量归档、重新确认使用、锁定、解锁和遗忘每次最多 100 条，全部先核对所有者与版本。重新启用后还检查当前有效期、冲突和来源；任何一项不满足则整批回滚。正常启用条目的本次归档可在 60 秒内撤销，并再次核对版本；原先已停用、归档或冷却的混合选择不显示一键撤销，避免错误激活。目录只返回每条最多 20 个冲突 ID 预览和完整计数，避免 10,000 条同键值生成平方级关联列表。确认冲突组时从服务端完整读取版本，不受当前列表页或搜索结果截断影响。

## 4. 有界自优化与执行可靠性

本地整理、保留期检查和反馈排序继续默认可用。语义复盘默认关闭，只对有模型授权的会话、当前允许的范围进行，产出先待本人核对。它不能直接改写人工锁定的事实，也不能从自己的输出或曝光次数推出新事实。

复盘作业增加执行令牌、最早重试时间和独立尝试账本。每天预算按 UTC 日计数，应用 AI 额度维持原有日期规则。删除某个来源或作业快照不会重置已经消耗的当日预算；重启也不会重复迁移同一次尝试。超过 180 秒的遗留运行状态按可能已计费的中断处理，不自动补发请求。

额度不足时保留排队状态，记录下次可尝试时间。真实失败可由本人明确确认后重试；接口核对失败版本、当前授权、输入指纹和是否已有活跃作业，避免重试旧输入或重复入队。外部请求开始前及提交提议前均检查执行令牌、来源、权限和设置，来源改变或旧执行被替换后丢弃结果。

流式复盘读取有最多 45 秒的整体检查预算，连接及相邻读取的超时最多 10 秒；实际中断还受正在阻塞的单次读取约束。只有完整结束的响应可以形成提议。终态快照正文保留期为 30 天，之后清空正文并保留输入指纹；尝试账本保留 31 天。界面显示真实作业状态和是否等待额度，没有估算准确率或虚构完成百分比。

## 7. 能力边界

本轮验证以合成工程案例、模拟模型和本地检索为主，没有新增真实付费模型请求。确定性版本/来源/范围正确性不等于开放语言下的语义质量已经达到某个准确率。仍采用本地词法、窄语义槽、来源与时效排序，没有部署稠密向量或独立图数据库。任意改写、复杂隐含矛盾和长期偏好变化仍可能需要人工核对；只提取有依据的内容，语义推断保持待核对。

状态计数不是质量分数，浏览器视口不是手机真机验收，单机检索耗时不是完整模型回答延迟或公网并发承诺。原有 10,000 条长期、80 条单会话暂存等容量上限保持明确，达到上限会返回可理解的状态，不宣称无限记忆。
