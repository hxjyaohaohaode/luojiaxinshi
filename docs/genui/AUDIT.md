## 风险与改造点

1. 增量更新不能重建整条消息，否则滑杆、输入焦点和手动滚动会丢失。使用带键节点复用和逐帧更新。
2. 旧模型强制纯文本 JSON，与混合流冲突。保留 JSON 外壳及引用校验，增量解码 answer 字符串后转发；不改动通知提取提示词。
3. 新能力不得破坏现有取消令牌、幂等、账号隔离、额度和人工核对；取消后仍拒收迟到输出。
4. 模型图表、计算和按钮都不能成为执行代码。共享组件目录、受限表达式、逐节点校验与白名单动作是必需边界。
5. 模型数据不能伪装成工具数据。可信数据由服务端独立注入，原始输出中的 data 操作不具备授信能力。
6. 交互控件的联动仅在本地计算；持久化进度使用显式保存动作，避免每次滑动触发网络和模型调用。
7. 存储使用附加表，保持基础 schema 4 可被旧版本读取；关闭开关或回退代码不删除原始流和快照。
8. 当前目录无 Git。只在此开发目录初始化本地版本库，先记录现有源代码基线，再按 Phase 提交；不推送、不纳入 `.env`、`data/`、`artifacts/`、`.venv/`。
9. 完整硬件、真实模型及真实推送仍未验证。新能力使用明确标注的离线夹具和隔离服务，不把夹具结果冒充模型质量。
