# 连续交互与逐项编辑

## 目的

生成式回答应能支持一段实际工作：阅读证据、逐项批注、作判断、修改草稿、
比较结果，再把当前选择交给模型继续。新增能力属于通用运行时和数据契约，
不要求模型选择“新闻页”“写作页”等固定模板。

`研读与改稿` 是虚构的综合验收样本。模型仍可自由组合原语用于其他任务。

## 可编辑记录的绑定

Collection 可声明 `bind: "records"`，指向 state 中原始记录数组；items 可以
使用该数组的筛选或排序结果。子树控件的 `bind: "item.note"` 写入当前记录的
note 字段。字段必须事先存在，输入类型、选项、范围和文本长度仍适用。

```json
{"op":"state","set":{"records":[{"id":"a","title":"材料甲","original":"只读原文","note":""}]}}
{"op":"node","id":"records","type":"Collection","props":{"bind":"records","items":{"$bind":"records"},"keyField":"id","columns":1},"children":["note"]}
{"op":"node","id":"note","type":"TextInput","props":{"label":"我的批注","bind":"item.note","multiline":true}}
```

运行时依据记录身份定位原始数组位置，不把筛选后的可见下标当成原始位置。
Collection 的 items 更新不重建整份容器；局部绘制保留输入焦点与光标。
多行草稿随内容和容器宽度调整高度；超过高度上限后保留输入区滚动，
在手机宽度或标签页切换后也重新测量，避免截住尚未滚动的短文。
同一条记录重排后仍使用同一组节点和视图身份。不能对仅来自只读 data 的
副本宣称支持原位编辑。

服务端展开这些声明，形成具体可编辑路径。未声明可编辑的来源字段不能
通过修改同类型字符串绕过保存检查。状态动作的固定候选值和嵌套输入可以
组合，例如切换情境后再作答；初始 null 的合法 Choice 也可以保存。

模型发布前的机械检查会验证输入路径、初始值、选项和本地动作路径，
错误进入已有的有界修正流程，不能把缺失绑定留给用户点击后才发现。

## 将当前工作带入下一轮

发送内容保持用户原来的文字。另附一个 `ui_context` 请求字段：

```json
{"v":1,"message_id":"当前回复ID","snapshot_version":0,"blocks":{"0":{"inputs":{"records.0.note":"这条表述尚缺回应"},"view":{}}}}
```

前端只投影声明过的输入和本地状态动作，不把整份原文数组重复当成用户输入。
逐项继续分析优先携带当前记录，其他记录的批注不被无关地打包。普通输入框
也能带入刚调整的当前界面；发送得到服务器确认后，不重复附带未变化的选择。
后续文字回答不会丢掉仍在使用的交互工作区。

清空、撤销或恢复默认值也作为一次当前选择更新，不能因为值又等于初始值就
丢弃它。普通状态输入、表单、未绑定的阅读分组与本地清单都保留这一语义。
重载时会对照已提交的逐项路径，防止旧上下文压过当前界面。

服务端在创建消息前核对：

- 原回复属于当前会话、已完成、通过验证，而且是当前选择的回复版本。
- 输入路径来自该回复的真实 Schema，客户端不能新增标签、字段或原文值。
- 静态选项、数值范围、步长、文本、清单、标签页和表单草稿符合约定。
- 请求与摘要有大小和数量上限；超限明确拒绝，不悄悄截断用户输入。

当前上限为 64 KiB 的原始交互上下文、40 项摘要、16 KiB 的摘要序列化内容；
完整互动快照仍受 128 KiB 上限约束。逐条按钮可缩小提交范围。

规范化后的选择写入 `genui_interactions`，与用户消息一起持久化。
对话重载与分支会保留它，并重映射源消息归属。消息可展开查看带入的选择。
检索规划、正文和独立核验都能读取这些上下文；联网授权范围仍只看用户原始
要求，不从旧界面标签或草稿中的文字推导新授权。

### 真实检索的访问范围

本轮真实调用暴露了“不读资料库和日程”仍触发账号检索的问题。
服务端现在在加载原始材料和构建模型上下文之前，分别约束资料库、日程与
个人档案；“只用官网”的明确要求跳过私有记录，但不关闭公开网页读取。
限制随会话保留，后续明确允许某一类别才恢复对应访问；界面标签、助手
回复和检索材料不能授予访问权限。阶段摘要也必须反映实际允许范围。

用户在普通消息中提供公开链接时，按现有域名与网络边界直接读取最多三个
页面，先读取用户指定原文，再由覆盖检查决定是否补查，不能依赖搜索引擎
恰好返回相同链接。读取保留来源 URL、正文段落与
实际字符编码；旧页面错误声明 GB2312、实际返回 UTF-8 时不再保存乱码。
原生联网每次处理一条具体检索式，带 site: 的请求剔除其他域名结果。
检索结果为空仍须据实保留缺口，不用模型记忆补出原文。

引用索引最多保留 120 个片段，按检索相关性排序、去重网页重复段落并轮流
保留不同来源。不能先按网页原始顺序截取：真实旧官网有数百段导航在正文
之前，这会让生成模型拿不到关键条款或第二份原文。排序只选择原有片段，
不改写引文、来源归属或段落定位；达到索引上限仍须保留覆盖限制。

### 模型分工与可修正的协议

Tier 1 编排现在使用 `ui:{state,nodes}` 结构化对象。模型自由决定内容、节点、
阅读次序和交互关系，服务端只负责生成 begin/state/node/end 协议封装；不再让
模型同时在一个 JSON 字符串中手写逐行 JSON。这样减少双重转义、遗漏结束行和
混用操作字段导致的整轮失败，既不选择整页模板，也不为控件补造业务初值。
历史围栏回答仍可读取。新对象与历史回答经过相同的目录、表达式、绑定、动作、
引文和独立核验门槛；协议转换不能放行非法控件或改变来源事实。

严格流程中 Pro 负责检索规划、覆盖与事实分析、正文和控件自由编排，以及
最终独立核验。证据已准备后，展示编排不重复开启思考，使用温度0.2减少
协议输出的随机性；分析和核验仍开启思考。Flash 负责短阶段工作摘要，
`MIMO_COMPOSITION_MODEL=mimo-v2.6-flash` 保留为可选对照，不能因更快而
跳过 Pro 独立核验。实际模型与思考模式写入 `grounding.models/model_modes`。
独立核验采用配置的 `AI_OUTPUT_TOKENS`（默认32768），包含思考与最终 JSON，
不再固定为12000。真实复杂任务曾耗尽旧核验预算而未能返回完整结论；预算
扩大不能保证速度或成功，整轮时限仍有效。程序已检查的结构与引文字面结果
传给审查模型，集中复核事实支持、限定条件、遗漏与交互承诺，避免重复推导协议。

新作者协议仅在正文和 UI 文本使用本轮稳定片段标记 `[E编号]`，结论清单填写
`claims.evidence_refs`。模型不维护位置编号或引文数组；服务端统一去重、编号，
恢复逐字原文，并同时转换正文、界面内容和结论清单。改稿重排也不会改变同一
标记的来源归属。原始引文不参与标记替换；未知片段、混用两种编号或超出引用
上限继续拒绝。核验意见提到的显示编号另附回稳定 ref 的映射，修正仍使用 ref。

旧的数字引用与 citation_refs 回答继续兼容，重复合法片段保留历史位置，冲突
引文继续拒绝。根层多余的空 citation_indices 仅作为兼容元数据丢弃，非空值拒绝；
该字段不能声明任何依据。新模型 Schema 不展示这些旧字段，避免空字段在不同
层级的重复说明造成生成歧义。任何协议都不能要求模型自行编造 source_id 或引文。

格式或内容核验失败后，下一次修正携带对应未发布草稿。格式错误的
answer 通道 JSON 受 128 KiB 上限约束，仅用于本轮授权的修正请求；
不包含 provider 的 reasoning_content，不进入用户错误提示或阶段摘要。
已通过对象解析、但后续程序或事实核验失败时，同样保留原生 ui 对象和
citation_refs 映射作为修正输入，不把编译后的 JSONL 围栏代替模型的原稿。
原稿只在当前内存中的修正链路传递，不发送到前端、落库或作为事实依据。
格式与交互协议最多额外修正3轮，事实语义复核最多额外修正1轮，合计
最多5次生成并受整轮900秒默认时限约束。检索结果在本轮复用；修正不能
跳过核验或只删掉用户需求。事实语义连续两次不支持时仍立即拦截，不以
增加协议修正机会来反复寻求语义核验放行。失败类别和问题写入修正记录。

初始值不等于用户确认，模型生成的标签不构成外部证据。上下文始终作为
用户参数和草稿解释，不能证明政策、资格或已经完成真实办理。

## 撤销、重做与提交

本地调整可以撤销、重做和恢复初始选择。连续输入会短时合并为一次编辑，
历史最多 20 项并受内存预算约束。恢复初始选择本身也可以撤销。
这些操作不会调用模型，也不会修改日程或提交真实事务。

显式保存进度保留当前状态和视图。提交界面上下文时会按快照版本保存一次
工作进度；其他页面已保存较新版本时，不覆盖那份进度，但仍保留本轮提交
的选择供模型分析，并说明冲突。撤销栈只存在于本次页面会话，重载后
从保存状态重新开始。复制和分享使用当前选中视角、逐项批注、选择标签和
表单填写值，避免交付时退回初始数据。

当前网页客户端携带快照版本。兼容旧调用方省略版本的情况：这些调用只保留
对话中的选择记录，不自动覆盖旧界面的进度。提交确认也只提示本次提交的
选择已保存，后续或未随本次请求发送的调整仍可继续编辑和显式保存。

模型动作显示等待状态并阻止同一控件重复提交。失败后恢复操作能力、保留
草稿并显示错误；用户仍可从主输入框发送补充。非法交互数据在中断旧任务前
就会拒绝，防止错误补充无故取消正在运行的回答。

## 验证边界

不执行模型生成的 JavaScript。服务端解析引用约束，不执行 UI 表达式；
由复杂表达式生成的选项或范围仍按用户参数处理，校验字段归属、类型和体积，
不能声称服务端已复现全部动态选项。静态和直接引用的约束执行更具体检查。
任何用户参数都不因通过这些检查而变成事实依据或外部操作授权。

测试覆盖逐项编辑的归属、筛选后的焦点与光标、只读数据保护、未作答状态、
情境切换、撤销重做、草稿预览、复制、等待与失败、跨轮上下文、重放、分支、
账号隔离、非法补充不中断原回复及真实 Pro 延续。
