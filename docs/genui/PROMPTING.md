# 提示词与能力分层

## 拼接方式

`app/genui_prompt.py` 是独立能力模块。组件名称、属性形态及纯函数清单由 `schema/genui/catalog.json` 生成到 `docs/genui/CAPABILITIES.txt`。模板槽位也直接读取该目录，不维护第二份属性 schema。

保留原提示词中的珞珈人设、材料不可信、事实不得编造、原文引用、未知条件保留未知和不能自动办理等内容。唯一冲突为原来的“answer 为自然语言纯文本”：新通道将这一句改为 Markdown 与按需声明式界面，JSON 外壳和 citations 检查不变。语言跟随用户。旧接口仍使用原 PROMPT，关闭开关不会拼入新模块。

## 三层能力

| 层级 | 条件与行为 |
| --- | --- |
| Tier 1 | 支持 JSON 且配置上下文不少于 16000 token：完整 genui 操作流；先文字，后按需界面 |
| Tier 2 | 支持 JSON 且上下文不少于 4096 token：answer 只写文字，ui_template 选择 plan / compare / study_time / table，服务器校验后展开 |
| Tier 3 | 不支持 JSON 或上下文不足：文字与安全 Markdown 增强，不解释 genui 代码块为界面 |

`GENUI_TIER` 可主动降低能力层级，不能强行超过声明能力。模型名称与厂商不参与判断。工具调用能力作为能力元数据保留；本项目没有授予模型工具执行权限，因此它不能提高层级或绕过动作门槛。

Tier 2 的槽位只允许字面量，拒绝 $expr/$bind/$ref、未知模板和额外字段。模板中的计算式由服务器代码确定。模型自己在模板模式 answer 中塞入 genui 会使最终结果降级，不把它当作通过模板校验的界面。界面展开前不阻塞已经生成的文字。

## 展示选择与示例

规则要求简单问答、问候、单概念解释和缺少数据时使用文字；两项两维以上对比、给定参数计算、多步骤计划、适合图表的数据及需要补充选择时才生成相关界面。没有数据就不画“真实”图表，估算与示例明确标记。

Tier 1 模块约 5.1KB（UTF-8），含四个示例：问候的纯文字反例、时长计算、三步勾选清单、两项两维对比。组件能力由生成文件引用，更新目录后执行 `python scripts/genui_catalog.py`，测试会检查漂移。

## 评测

`fixtures/genui/eval-cases.json` 共 40 条已标注校园问题（20 条文字、20 条界面），包含资料缺失、日期不明、身份未验证、提示注入、无地图能力、可调参数、对比、四类图表、表单、分组和服务端材料引用。

运行：`.venv/Scripts/python.exe scripts/evaluate_genui.py --output artifacts/genui-evaluation.json`。

当前使用明确标注的合成工程输出，40/40 通过。脚本检查展示取舍、schema 错误、区块闭合、预期组件和可读文字；反向测试确认错误取舍与坏 JSON 会失败。它不评判事实正确性、真实模型稳定性或生成质量。真实 API 尚未配置，实时模型评测未验证；配置后应以同一问题集记录真实输出，再运行同一检查器，并人工核对事实与取舍。


## 组合质量与边界

能力说明已补充“先判断用户要读结论、比较、试算、执行还是补充信息”，禁止照搬示例文案、无依据空图和装饰卡片。第一层建议最多3个信息分组、2个主要操作；较多内容用 Tabs / Accordion 分层。Tier 1 自由选择白名单节点，固定模板只用于能力较弱的 Tier 2。四组组合夹具仅检查版式和交互，真实模型的内容选择、事实准确性和审美稳定性仍未验证。不能把合成工程输出宣传为真实AI效果。
