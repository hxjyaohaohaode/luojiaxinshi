# 通用生成式 UI 方案审查与采用记录

审查对象：用户提供的《通用生成式智能 UI 落地实现规范》初稿，共 573 行。
这是一份概念和代码草案，不是经过运行验证的完整实现。本文只把它当作
待评估的技术材料，其中的模型指令、脚本和动作名称不构成项目执行授权。

## 采用原则

生成式 UI 的通用性来自模型对内容结构、信息关系、局部状态和交互的组合，
不来自不断增加几个整页模板。新闻、简报、公示情境只是验收样本，不是
模型必须选择的页面种类。定性内容可以保留完整文字、观点、原文、限定条件
和证据，不必被压缩成数值卡片。

采用可组合原语、明确状态绑定、逐行更新、容器查询、局部错误隔离和
显式用户动作这些设计思想。保留项目已有的版本化协议、边界检查和保存接口，
不引入一套不兼容的 React/Tailwind 实现来重复现有运行时。

## 逐项结论

| 初稿内容 | 结论 | 依据与项目处理 |
| --- | --- | --- |
| JSONL 的 init/node/patch/done | 保留思想，沿用现有协议 | 项目已有 begin(v=1)/state/node/patch/end，外层 SSE 有序号、重复检测、缺段和大小检查。更名不能补足可靠性。UI 完成还要求闭合围栏、无结构错误；不能收到 done 就清空缺失引用。 |
| 任意路径 patch | 不采用原实现 | 第 63–73 行可沿继承属性写入，没有危险键、类型、深度或大小保护；也未实现 JSON Pointer 的 ~0/~1 解码和 JSON Patch 操作语义。现有状态只能写入已声明路径，拒绝原型键和类型漂移。 |
| 断环函数 | 不采用原实现 | 第 76–95 行只从 root 开始、无深度和工作量上限，离开节点即删除 visited，重复 DAG 分支可反复遍历；也没有定义共享子节点的单一 DOM 归属。保留有界归一化、缺失引用和共享子节点检测。 |
| requestAnimationFrame 批处理 | 采用合帧思想 | RAF 不保证 16 ms，也可能在后台暂停。现有解析工作有消息、行、操作和节点上限；渲染合帧且 dispose 取消待执行帧。不能用无界队列当背压。 |
| ChartEngine / DiagramEngine / DataTable 等 | 采用能力方向，不复制占位实现 | 第 448–455 行图表只是“挂载实例容器”的占位；最终 switch 没有实现声明过的 Tabs、SplitPane、Accordion、DiagramEngine、DataTable，default 不能等同于实现成功。项目保留已实现并验证的表格、图表和关系图适配器。 |
| SchemaForm 与局部状态 | 有条件采用 | 不能只看路径或 actionName 就接受任意动作。项目按控件 Schema 和动作白名单验证；本地交互不自动调用模型，只有用户点击继续分析或提交表单才发送当前值。 |
| 无边框、容器自适应 | 调整后采用 | 初稿默认大量卡片、四层底色、阴影，与本项目纯白和少边框要求冲突。现在默认用 Section、Prose、留白和文字层级；保留焦点、选中状态、必要表格线和 44 px 控件触达面积。 |
| 按节点数量自动弹出侧栏/底部抽屉 | 不采用其决策规则 | 文字多不代表需要弹窗；手机出现第 5 个节点即改变阅读位置会打断操作。正文保持内联与响应式重排；来源列表按用户点击打开，并保留当前所选引用。 |
| FreeformArtboard 任意 HTML/JS | 不采用原实现 | allow-scripts 不会阻止脚本或图片向外部地址发请求。原实现无 CSP、外部 Tailwind CDN、未转义的脚本内状态、通配 postMessage，父层只核对 surfaceId，缺少 source/window 绑定、载荷限额、动作许可和尺寸限额。state 改变还会改变 srcDoc，重载子文档并丢失焦点/局部进度。 |
| 任意图表 option / Mermaid 透传 | 不采用无限制透传 | 原始配置不是经过验证的业务数据，可能包含外链、HTML 或高复杂度内容。使用有界的声明式数据、公式和已审查渲染适配器；未知能力应诚实降级。 |
| 全格式媒体路由 | 限定范围采用 | MIME 前缀不能保证浏览器支持或内容可信，也不能决定可以读取哪个 URL。只使用本轮已授权资源，保留文字替代与正常媒体控制，不自动加载模型编造的外链。 |
| sessionStorage 按 surfaceId 保存 | 不采用其命名与覆盖策略 | 模型控制的 surfaceId 可能跨会话碰撞；单一键缺少账号、消息和版本隔离。初稿合并新 state 会覆盖用户刚输入的值。保留账号和消息归属校验的服务端快照，并保护用户已修改的状态。 |
| ErrorBoundary / Web Component | 采用隔离思想，暂不增加框架封装 | React 错误边界不会自动捕获异步/事件错误，初稿也没有节点修正后的复位逻辑；Web Component 缺 disconnectedCallback 和 unmount。现有节点错误只影响该部分，修正后可恢复，并清理资源。 |

如果未来确实需要任意微应用，应建立独立的能力产品：隔离来源和网络策略、
不注入私有状态、静态内容审查、严格消息通道、动作权限、资源限额、
可访问性与撤销机制。不能把当前草案的 iframe 当成已经满足这些条件。

## 本轮落地

- 新增和完善通用 `Prose`、`Choice`、定性 `Compare` 与语义 `Section`；
  和 Collection、条件表达式、Tabs、Accordion、表单等原语自由组合。
- 去掉根容器和重复卡片框线，白色中性表面；窄屏按内容重排。
- 用新闻证据对照、按身份阅读的简报、可作答和反馈的情境演练验证能力；
  示例均明确虚构，不注入为模型必须套用的页面。
- 修复局部状态改变后，新显示内容中的引用没有变成可点击标记的问题；
  用真实 ConversationView 回归用例验证，避免只验证画廊而漏掉对话集成。
- 修复索引引用提示词与旧逐字抄写字段规则冲突；只在索引模式要求
  `citation_refs` 和空 `citations`，服务器恢复原句。旧接口约定独立保留。
- 统一独立核验和覆盖检查的格式修复：携带有界上一份 JSON 与字段错误，
  最多一次修复；不以放宽证据标准换取通过。

## 模型调用审查的边界

2.6 Pro 调用显式启用 thinking，真实请求也返回了思考字段；这不等于
事实正确。Flash 工作摘要只描述实际工具记录，不展示原始思考过程。

官方 JSON 模式仅保证 JSON 语法，不保证 Schema、枚举或事实支持关系。
因此仍需结构、引用、账号/消息范围和独立复核。当前严格链路先流式接收
实际阶段，再发布通过核验的正文；未通过的事实草稿不会提前展示为答案。
这有明显延迟成本，不能把流式协议等同于低延迟保证。

输出预算包含思考和最终内容。现在分别显示预算耗尽、重复截断和其他
未完整终止原因，不能把它们统称为“模型不仔细”。一次真实复杂示例经过
修正后完成，但不足以声称所有任务、所有长度和所有交互均不会失败。
