# ADR-009：核对页面的用时观测

状态：已实现，1.12.0，2026-10-18。本文是工程契约，不是用户研究结果。

## 问题

原 MVP 要求允许修改草稿、保留改动并记录纠错耗时，最终比较从收到通知到保存行动及设置提醒的总办理时间。现有审计保存修改前后内容，执行记录保存模型阶段耗时，但没有核对页面的用时记录。只看供应商耗时无法判断真实流程是否更省时。

## 当前选择

使用本地浏览器观察当前一次打开的草稿页面。`ReviewClock` 以单调时钟计量，只有页面可见、窗口有焦点且最近 60 秒内有操作时累加；编辑区获得焦点时的活跃时间计入其子项。提交前冻结快照并暂停，网络等待不计入；拒绝后可继续核对，重试使用新快照。切页、刷新、关闭后不拼接旧时段。同一通知版本在本页重新渲染不会重置，切到另一版本或账号重新开始。

这些数字是浏览器报告的估算，不能证明用户一直在阅读或纠错。编辑区停留包含阅读，不能标成“纯纠错时间”。重新打开之前的工作、页面外查证、准备材料、模型等待和日历操作都可能未计入，不能冒充完整办理耗时。真实研究仍须按原方案独立记录整段任务时间及观察到的纠错过程。

页面以可展开的“核对用时（本次页面）”说明统计范围；确认后可回看。没有按键内容、鼠标轨迹、用户输入副本、屏幕录制或外部遥测。为避免错误时钟或超长空置数据，两个数值均限制在 8 小时内，到达上限明确显示。

## 数据与兼容

服务端通过 `review_observation_contract=1` 声明能力。确认请求可选 `review_observation`：

```json
{"method":"visible_idle_60s_v1","active_ms":61234,"editing_ms":15000}
```

方法版本固定；毫秒值为严格非负整数，编辑区时间不能超过页面时间，未知字段拒绝。没有记录时保持缺失，不填成 0。旧客户端与手工 API 可继续确认；前端遇到旧服务不提交新字段。此观测由客户端提供，服务端校验结构与范围，不将其认证为真实研究数据。

记录与任务确认、逐条意见处理在同一事务提交；任何验证失败均不写入。重放相同草稿版本返回原任务，不覆盖原用时。原始修改内容继续由现有 `confirm_draft` 审计保存，计时不影响任何期限、办理状态或任务数量。

`quality_receipt.observation` 保存该可选记录，个人 JSON 导入保留为历史，并继续校验范围；导入不是重新计时。旧导出没有该字段也能导入。账号归属与删除级联沿用通知审计机制，没有增加表、配置项、运行依赖或模型请求。

## 验证

- `tests/review-observation.test.mjs`：空闲上限、后台暂停、编辑子集、提交冻结、重试、单调时间边界、记录上限和历史展示。
- `tests/test_review_observation.py`：非法数值和未知字段的原子拒绝、可选兼容、重复提交不改写、跨账号隔离与 JSON 迁移。
- `scripts/verify_review_observation_browser.mjs`：真实 DOM 事件和 HTTP 确认、拒绝后重试、重新打开、保存回看、三引擎六尺寸；无模型请求。

完整执行结果以 [验证记录](../TESTING.md) 为准。日后需要跨设备、跨页面连续研究计时，应另建明确的研究会话与同意、去重和观察协议，不对本字段无声地改变含义。
