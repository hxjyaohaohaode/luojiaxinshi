# 珞珈信使记忆功能升级说明

本次升级把长期、经历、会话短期、仅本轮条件、工作记忆、Agent 提议、人工校订、来源追踪和后台整理接入现有 FastAPI / SQLite 系统。主要设计参考 EverOS，并吸收 Hindsight、MemOS、LangMem、Graphiti 等项目中适合现有系统的机制。默认整理在本地执行；另提供默认关闭、有授权和每日预算的语义复盘。完整形成/使用/遗忘路径见 [生命周期 v3](MEMORY_LIFECYCLE_V3.md)。没有新增云端记忆服务。

## 1. 已实现的功能

| 功能 | 实际行为 |
| --- | --- |
| 八类长期记忆 | 表达与做事偏好、约束与边界、已确认决定、本人提供的信息、经历与办理记录、技能与方法、待办与计划、分类概览 |
| 使用范围 | 按登录用户隔离；支持通用、项目和专题。召回先限制当前范围，再做全文检索和排序 |
| 会话与本轮记忆 | 临时要求保留在原会话及形成范围，支持保留期、人工编辑晋升与遗忘；仅本轮条件下一轮退出调用 |
| 对话工作记忆 | 按对话及项目/专题组合保存目标与进展，栏目增量合并；可手动修改、锁定，使用版本号避免覆盖较新编辑 |
| Agent 管理 | 在当前回答的结构化结果中提出 remember、update、archive、derive、checkpoint、use、forget；服务器校验来源、目标、权限、版本及有效性后执行 |
| 自动学习 | 对用户原话中保守识别的稳定信息进行提取；办理记录变化进入持久队列；推断、改写和敏感操作优先待人工核对 |
| 人工管理 | 新增、修改、标签、置顶、停用、删除、有效期、同类键、锁定保护、查看来源、版本历史与恢复 |
| 自行整理 | 按范围和类型生成分页概览；保留所有原始记录；增量执行、失败可重试、来源变化会让派生记录失效 |
| 导入导出 | 独立记忆 JSON 归档、Markdown 导出编辑再导入；JSON 导入内容默认待核对且不自动启用 |
| 真实执行回执 | 聊天回复下方显示服务器实际记录的已保存、待核对、未保存等状态，不能以模型口头承诺替代保存结果 |
| 使用反馈与生命周期 | 分别记录提供、Agent 报告采用、本人反馈；过时暂停调用，支持跨会话开关、场景提示、自动冷却及防历史重新学习 |

记忆用于理解用户背景和协助办理。个人记忆中的“已完成”只是用户自己的办理状态，不能替代通知原文、官方回执或真实外部提交。

## 2. 如何使用

打开应用的“我的记忆”，点击记忆设置，可在四种模式中切换：自动学习、先核对再保存、仅手动维护、关闭记忆。关闭模式停止学习与调用；仅手动维护保留已确认记忆的调用。对话中也可以单独关闭记忆或限定使用范围。

新建记忆时选择类型和范围，填写具体内容。需要长期保护的内容保持“锁定”开启；Agent 对锁定内容的修改只能生成待核对提议。标签适合检索整理；置顶只在允许的范围内提高优先级，不会突破项目或账户隔离。

例如可以告诉 Agent：“记住，我希望回答先给结论，再给依据。”当前模式、来源及校验结果决定它会直接保存还是等待核对。看到聊天下方的实际回执后，可进入“我的记忆”检查。模型在正文里说“我记住了”，本身不构成保存成功的证据。

待核对记录可以接受或拒绝。接受前会重新检查依据版本；如果原始信息已经改变，需要重新整理。人工接受后会锁定记录。拒绝会删除提议，并阻止相同来源被后台反复自动学习；需要重新加入时可以人工新建。

点击记忆的详情可以查看来源、派生关系和修改历史。恢复历史版本会产生新的当前版本，并保留来源链。恢复旧版本不绕过来源有效性检查：办理记录已经变化时，旧记忆仍可能处于“来源已变化”状态而不参与召回。

对话中的工作记录适合保存“当前目标、已经做到哪里、下一步”。手动编辑并锁定后，自动流程不会覆盖。它属于当前对话，不会自动变成全局事实。

“整理记忆”处理当前可处理的队列并生成分类概览；“整理历史”显式回看既有对话和办理记录。日常自动整理会避开正在生成回答的账户，避免后台整理让当前回答的依据版本突然改变。

JSON 用于归档和迁移。Markdown 用于熟悉的文本编辑：保留文件中的记录 ID 和版本元数据，修改正文后导入；如果记录已被别人或另一个窗口改动，服务器会拒绝旧版本覆盖。跨账户或跨安装导入的来源历史只作为带标签的档案保存，不会冒充本机可验证的实时来源。

## 3. 记忆生命周期与一致性

入口包括用户手动保存、用户消息的保守提取、Agent 的结构化提议和个人办理状态变化。每条记忆都有所属用户、范围、类型、版本、时间、审核状态和锁定信息；有来源的记录保存原始引用和来源版本。

只有已确认、当前有效、范围允许且来源没有失效的记录进入召回。同类键表示同一范围中只能有一个当前值的信息；当前实现对明确配置的键进行冲突处理，不宣称可以自动识别所有自然语言矛盾。项目范围优先于专题，专题优先于通用；同一层级存在不同值时暂停调用相关冲突内容。

有效期与事件时间分开处理。某项申请的截止日期并不意味着“关于申请的记忆”届时应被删除。没有明确配置的有效期不会从正文中的日期猜出失效时间。Agent 提议带时间条件的记忆需人工核对。

编辑记录会新增历史版本，并使依赖旧版本的派生概览失效。删除源消息、源对话或相关任务会清除依赖记录；删除记忆会维护索引、来源关系和拒绝再次学习的标记。后台因为来源变化而移除概览，与用户明确删除概览分开处理，确保正常重建和用户遗忘意图都被尊重。

数据库更新、索引、历史和队列使用同一 SQLite 事务。待处理任务保存在数据库里，进程退出后仍可重新处理。失败作业保留状态和有限错误说明，支持重试；达到容量限制时不吞掉用户消息。

## 4. 检索和上下文控制

检索使用 SQLite FTS5、中文单字与双字切分、ASCII 词项、BM25、透明词汇扩展、窄语义槽、规划器检索词和会话指代，以及范围和来源关系。多个结果通道在名次空间融合，再用 MMR 控制重复，结合时效和本人反馈排序；无关置顶不强行进入候选。旧任务经历需要具体事项或个人进度/回顾意图。

候选范围在 FTS 查询截断前就完成过滤，避免别的项目大量同词记录挤占当前范围的结果。输入模型前再次检查有效期、冲突和派生来源，减少过期记忆进入回答的机会。

每次普通回答最多选取 12 条长期记忆，记忆序列化预算为 8,000 字节；工作记录及其他业务上下文有各自上限。这个预算包含记忆元数据，不能把原文长度当成模型实际收到的全部长度。管理员历史、导入档案和完整版本链不会随普通回答一起发送。

当前没有启用稠密向量、外部 embedding 服务或重型图数据库。关系只用于追踪来源和局部补充检索。因此，当前性能结果不能等同于开放领域语义记忆基准。若以后引入向量召回，应继续保留范围前置过滤、来源检查与现有本地召回回归。

## 5. Agent 能做什么，服务器如何约束

模型可以提出新增、更新、归档和基于已有记忆生成派生记录。操作目标必须属于当前登录用户；自动来源必须绑定到当前对话的最新有效用户消息；引用必须能在该消息中核实；更新必须提供当前版本号。

直接引用稳定信息才可能自动接受。推断、改写、带时间条件的提议、派生内容和对锁定记录的修改进入待核对流程。引述、假设、第三人称描述、疑似指令注入和常见密钥形式有保守过滤，但规则识别不是普适的语义保证；人工仍可核对所有来源。

范围也受服务器约束。默认沿用当前项目；只有明确提出通用范围时才申请全局保存；专题只能选择当前对话已选专题。Agent 不能通过伪造其他用户 ID、项目 ID 或历史消息 ID 扩大权限。

只有回答成功完成且通过原有发布检查后才执行模型提议。取消、失败或版本冲突的回答不提前提交其操作。原始用户消息的保守提取是独立流程：即使模型后来失败，用户明确表达的稳定信息可能已经被记录，这与模型推断保存必须区分。

实际执行结果会进入服务器回执，也可以作为后续对话的有限上下文，防止 Agent 把待核对或被拒绝的内容说成已经生效。自动工作记录会遮蔽常见密钥形式；用户手动输入的原文及原有聊天历史仍按原应用的数据功能处理，不能宣称系统已经消除了所有敏感信息。

## 7. 明确的容量与运行边界

每个用户最多保存 10,000 条记忆，单条正文最多 2,000 字符，标签最多 8 个。独立 JSON 导入最多 10,000 条、请求文本最多 20,000,000 字符；极大的完整版本档案可能需要数据库备份而非单次 JSON 导入。完整 SQLite 备份是恢复全部关系、工作记录和作业状态的途径。

概览按范围、类型和稳定顺序分页，一页最多合并 12 条且内容受长度限制；超过适合合并长度的原始记录仍直接保留并参与检索。每轮最多新增 16 个概览，后续轮次接着处理剩余页，避免大账户一次占用长事务。少于 3 条的分组无需额外概览。

后台默认每 10 秒检查一次待处理任务，一次有界处理；没有新变化的账户不反复全量重整。达到容量限制时提示并保留失败状态。本地整理生成保留来源的确定性分类概览，并执行保留期、冷却和重复依据晋升。语义归纳由当前 Agent 提出，或在本人开启复盘后由摘要模型生成待核对提议；默认每天最多 2 次，仍受原 AI 额度限制。

自动学习和整理沿用本地账号的数据权限，未新增独立服务、外部网络监听或云端同步。可选模型复盘可能计费，默认关闭，且需要已有外部模型处理授权；失败或中断不会自动再次付费请求。普通聊天继续遵从原供应方和用户控制设置。

## 8. 运维与复现

修改代码后按现有启动方式重启本地服务。数据库初始化会从既有结构或记忆 schema v1/v2 迁移到 v3；升级前保留 SQLite 一致性备份。不要直接复制仍在写入的数据库文件来代替 SQLite backup API。

后端测试：`.venv\Scripts\python.exe -m pytest --override-ini addopts= -q`。

前端逻辑：`npm test`。

容量基准：`.venv\Scripts\python.exe scripts/benchmark_memory_engine.py`。该脚本创建独立合成数据库，不读取真实账号内容。

浏览器验收：先用 `scripts/memory_engine_preview_server.py` 启动 8786 端口的隔离夹具，再运行 `scripts/verify_memory_engine.mjs` 与 `scripts/verify_memory_lifecycle.mjs`。如 Playwright 未安装在当前 node_modules，可通过 PLAYWRIGHT_PATH 指向已安装模块。夹具使用明确标注的模拟模型回复，不能当成真实模型效果实测。

最新实际测试结果见 [TESTING.md](../TESTING.md) 和去账号化的 [v3 验证汇总](verification/memory-lifecycle-v3.json)。此前交付目录保留原轮次的源码清单、报告及渲染记录；不把不同日期或不同范围的累计测试数相加。
