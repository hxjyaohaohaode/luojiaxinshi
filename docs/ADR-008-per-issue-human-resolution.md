# ADR-008：逐条处理复核意见与历史记录迁移

日期：2026-10-18。实现版本：1.11.0。状态：采用。

## 问题

原 MVP 要求对照原文核实事项、日期、责任人、材料及办理条件。1.9.0 增加了独立模型复核，但确认入口只检查一段至少八个字的总说明，不能知道多条意见各自怎样处理，也不能区分真实修改和口头声称已改。

1.10.0 的保留真实样本有四条意见：奖励申报缺少原文依据、参赛纪律遗漏、两处重复提及榜题立项名额。要求用户为每条意见复制一段总说明会增加核对成本；直接把所有意见改成个人任务又会制造新的手续。

## 当前确认契约

新增本地模块 `notice_resolution.py`，独立于供应商调用模块。通知详情返回 `quality_resolution_contract=1`。存在待核对意见时，确认必须携带所选步骤到原草稿的 `source_indices`，以及完整、无重复的 `issue_resolutions`。

| 本人处理方式 | 确认前检查 |
|---|---|
| 已修改关联内容 | 关联实际选中的步骤；其办理内容、分类、条件或前置须存在改动。只改私人备注、调整显示顺序、把未修改的原步骤标为“新增”，不算纠正 |
| 相关步骤本次不保存 | 原步骤不在保存范围中，也没有以原样“新增”重新加入；整体漏项不能使用这一方式。页面按实际勾选自动记录，减少重复操作 |
| 作为办理注意事项 | 仅用于整体层面的条件、义务或适用性意见；本人填写至少八个字的依据。具体步骤、期限或交付遗漏不能仅标为一般注意事项 |
| 意见不适用 | 保留原意见，并填写至少八个字的本人依据；不要求接受模型误报 |

未完成独立复核时没有完整意见清单，页面保留总说明，并要求明确勾选已经逐份人工核对。普通手工流程和没有复核意见的草稿继续使用原有的逐项确认。

程序检查的是结构、关联、实际改动及本人记录，不会证明文字语义已经改对；小幅无效修改或不实说明仍需真实用户和样本评测发现。模型未提出意见也不代表全部要求正确。没有把人的说明升级为学校认证，没有新增模型请求或自动改写循环。

## 一致性与兼容

- 草稿原始身份独立于显示顺序，选择和重排不会把意见关联到另一项。新增手工步骤可以关联整体漏项。
- 所有处理选择、说明和新步骤沿用账号隔离的编辑暂存。旧版总说明保留供回看，但不能替代逐条处理。新前端面对未提供契约的旧服务继续发送原确认格式。
- 提交前冻结步骤及处理选择；等待暂存或网络请求期间的其他页面操作不改变已提交快照。编辑后重新确认最终核对勾选。
- 服务端依据数据库里的当前复核意见校验，在写事务内检查版本、处理清单、步骤和办理计划。任何失败整批回滚，不创建部分任务。重复提交已成功版本仍返回原任务 ID，不再次写入处理记录。
- 审计保存原始草稿和意见、本人处理、所选步骤索引及当时标题。确认页直接显示可读记录与原文入口；旧记录不会被补造成曾经逐条处理。

## 导出、恢复与权限

不新增数据库结构。SQLite 备份沿用现有审计表完整保留记录。个人 JSON 导出包括当前通知的核对记录；追加导入时按白名单、长度、索引及版本校验，保存为独立的 `import_quality_review` 历史事件，不伪造当前应用的确认操作。

导入历史明确标为未对当前材料重新核实。原句来源重新绑定到本次导入的材料，缺失来源保留引句而不生成跨账号跳转；再次导出和导入保持这一状态。任务期限、外部条件及提醒仍执行已有的重新核实规则。全部历史镜像和附件原件恢复继续使用 SQLite；本功能没有将个人 JSON 变成完整数据库镜像。

## 界面与验证

每条意见的正文可折叠，处理方式可直接选择；不适用的关联控件隐藏，窄屏使用短选项与至少 16 像素字号、44 像素控件。说明按内容增长到有限高度，滚动定位避开固定导航。原文、模型意见和本人说明分别展示。

真实保留草稿在隔离数据库内验证四种处理结果、重排、暂存重开、无实际修改时拒绝及保存后回看；复核不可用使用明确标注的工程夹具。均不调用模型、不写正式库。Python 回归覆盖缺项、重复项、伪造关联、只改备注、导入边界、账号隔离、连续迁移和回滚。证据与实际检查数见 [TESTING.md](../TESTING.md)。
