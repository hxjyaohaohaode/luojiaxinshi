# 珞珈信使

本地优先的校园通知与行动助手（1.15.0）。从原始通知出发，核对本人行动，准备材料，记录提交、补件、结果和后续跟进。正式变更先核实再应用；变化传到后续步骤，保留历史进度并由本人复核是否仍有效，或重新办理。个人计划与办理记录保留，并使用日历安排课程和事项。支持 AI 自动选取、持续维护、本人可编辑且有来源与遗忘边界的分层记忆，以及保留原始记录的长对话压缩；模型任务中断与过时结果都有可查看的处理状态。

界面统一页面宽度、颜色、字号、留白与触控尺寸；日历工具栏按实际内容宽度重排，月格按剩余高度显示预览并准确计数，短屏可在月历内部滚动。长弹窗保留标题与操作区，动效偏好可以保存并跟随系统设置。手机导航菜单关闭、切页或切换到桌面宽度后，旧聚焦回调失效；弹窗打开时，底层菜单暂停焦点限制。基础样式入口为 `static/interface.css`，品牌组件适配为 `static/workbench.css`，各尺寸效果与交互证据见 [验证记录](TESTING.md)。

工作台使用来信主卡、可切换的重点事项、真实统计、七天期限条、行动清单与完成圆环；待办支持看板/清单，通知资料支持卡片/列表，两种视图共享筛选。提交通知提供可回退的步骤条、实时收件预览、材料概览、附件缩略图与逐项移除。来源快速入口和记忆范围筛选帮助整理常用信息。全局搜索支持标题、材料和来源，按行动/通知分组；可用 `/` 或 Ctrl/Cmd+K 打开，方向键选择、Enter 打开、Esc 返回。

共按本地手册适配 29 类组件结构与交互模式；共享动效层统一数字滚动、卡片入场、局部光斑、按钮波纹、面板切换、原文阅读位置和可暂停的操作反馈。装饰只在可见前台运行，并遵循系统减少动效与个人开关。文件只在保存表单时上传，刷新或退出后重新选择；非法批次不会覆盖已有附件或草稿中的文件名。选型、页面覆盖与原生实现边界见 [组件手册适配记录](docs/FRONTEND_HANDBOOK_ADAPTATION.md)。

草稿每次打开与提交都保留对应的编辑版本。旧提交只清理它自己的暂存内容，新文字与附件记录继续保留；迟到响应不会替换后来打开的页面或弹窗。保存按钮保持尺寸并显示处理状态，失败后可以重试。个人条件、表达偏好与学期设置按字段更新，同一字段发生并发冲突时展示最新值供核对。

日历连续新建使用独立提交标识。安排已经保存但响应丢失或旧草稿未清理时，可核对当前已保存记录；查看保留草稿，另建或清空后新建均需明确选择。已删除安排的旧创建请求不会自动重建；旧版后台未升级时保留原有编辑并提示自行核对。代码版本与实际运行状态、升级边界见 [验证记录](TESTING.md)。

通知草稿按原文核对责任人、日期、材料、分类与前置。独立复核提出意见后，逐条记录已修改、不保存、作为注意事项或不采纳的依据；服务器检查实际改动与步骤关联，保存后可回看原意见和本人处理。没有完整模型复核时，明确走人工核对。详见 [逐条处理契约](docs/ADR-008-per-issue-human-resolution.md)。

维护者启用后，通知页可按次选择费用较高的“速度优先”；默认配置保持不变。两种方式均保留已启用的独立复核、原文校验和本人确认，不自动重试收费请求。处理记录保留实际阶段、模型与已返回用量。实测及边界见 [验证记录](TESTING.md)，路由与费用取舍见 [ADR-007](docs/ADR-007-notice-processing-modes.md)。

核对草稿时可以查看本次页面的活跃用时和编辑区活跃用时，确认后保留在核对记录及个人导出中。后台、空闲和提交等待暂停计量；这些是浏览器估算，不是纯纠错或完整办理耗时。原 MVP 各项实现、证据与仍缺的真实验收见 [完成情况映射](docs/MVP_COMPLETION_AUDIT.md)。

**同学第一次拉取请先看 [协作开发指南](CONTRIBUTING.md)**。项目方案、接口调研、核验底稿和原创视觉稿已包含在 [项目资料](项目资料/README.md)；所有运行时图片、图标和视频均在仓库内。本轮功能、MVP 对照和完整版衔接见 [办理闭环与演进契约](docs/MVP_WORKFLOW.md)，当前验证结果见 [TESTING.md](TESTING.md)。

新对话默认自动选择相关项目与专题记忆；普通对话可以直接积累和更正记忆，通知资料、上传全文、项目说明与办理进度也会自动参与维护。记忆卡片可手动编辑，或选中某段让 AI 修改并保存；资料来源变化会立即停用旧索引，后台更新。实际机制、收费调用与质量边界见 [自主记忆 v5](docs/MEMORY_AUTONOMY_V5.md)。

## 现在开始使用

1. 双击本目录的 **`启动工作台.cmd`**。服务在后台运行，浏览器自动打开。
2. 默认可在登录页直接创建账号；受邀试点模式须使用维护者提供的一次性邀请链接。选择自定义账号名、学号、工号或手机号，自行设置至少 12 个字符的密码。首次管理员仍通过本机一次性邀请建立，不向公开注册账号自动授予管理权限。
3. 保存注册时显示的一次性恢复码；忘记密码可凭它重设。从“办理工作台”处理通知并跟进行动；也可以在“和小信使聊聊”中上传材料、补充问题。在“个人与账号”填写对判断有用的校园条件。
4. 在“个人与账号 → 我的记忆”保存常用偏好、项目背景或已确认决定；在聊天输入框的“＋ → 项目与记忆”选择本次项目与专题。“记住我刚才说的”会先打开可编辑的确认表单。
5. 在“个人与账号 → 模型与处理记录”查看配置的模型、计费通道和最近处理记录；中断或过时的任务可打开原记录，核对后重试。不会自动重复提交收费请求。
6. 在待办的“变更待核实”筛选中处理新要求和办理影响。打开事项后点“核对办理影响”，先核对前置步骤，再说明原进度仍有效或选择重新办理；旧回执和个人备注保留。

固定访问地址：<http://127.0.0.1:8765>。管理员首次注册链接也保存在 `data/admin-setup.url.txt`。注册后使用自己的账号登录；维护者可通过本机命令管理邀请，普通用户界面不提供成员邀请入口。学号、工号和手机号只是自填账号名，不代表学校或短信验证；微信与 QQ 联系号可在个人资料中登记，平台授权另行管理。

关闭浏览器不会停止服务。需要停止时双击 `停止工作台.cmd`，修改配置后双击 `重启工作台.cmd`。重启电脑后再运行启动入口。重复启动会复用本目录的已运行服务，不会重新覆盖数据库。

本机模式监听回环地址，只在这台电脑上访问。之后部署服务器时沿用同一应用和数据结构，见 [OPERATIONS.md](OPERATIONS.md)。

按原 MVP 方案开展受邀试点时，在 `.env` 中设置 `REGISTRATION_MODE=invite` 并重启，再通过本机维护命令生成成员邀请。已有账号仍可登录；`public` 保留公开注册。该配置不代表已经完成真实用户试点或校园部署验收。

页面按电脑、平板和手机的浏览器宽度自适应，支持鼠标、触屏和键盘操作。无需给每个硬件型号分别安装客户端。当前提供 Windows 本机启动入口；部署到服务器后，其他设备通过 HTTPS 地址登录同一工作台。响应式验收尺寸及尚待真机验证的系统见 [TESTING.md](TESTING.md)。

## 配置小米 MiMo

项目的全部模型调用统一使用小米 MiMo。编辑本目录 **`.env`**，填写 `MIMO_API_KEY` 后重启，文字与语音模型配置已预置：

```dotenv
MIMO_API_KEY=在本机填写小米按量 API 密钥
MIMO_BASE_URL=https://api.xiaomimimo.com/v1
MIMO_TEXT_MODEL=mimo-v2.6-pro
NOTICE_SEMANTIC_REVIEW=true
MIMO_NOTICE_REVIEW_MODEL=mimo-v2.6-flash
MIMO_ASR_MODEL=mimo-v2.5-asr
MIMO_TTS_MODEL=mimo-v2.5-tts
MIMO_VOICE_DESIGN_MODEL=mimo-v2.5-tts-voicedesign
MIMO_VOICE_CLONE_MODEL=mimo-v2.5-tts-voiceclone
MIMO_TTS_VOICE=mimo_default
```

主模型负责多轮问答、截图理解、结构化提取和互动回答。语音输入使用 MiMo ASR；“个人设置 → 语音播报”提供普通播报、音色设计和授权声音复刻。全部请求经服务端发送到小米，密钥不进入浏览器。旧的 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL` 已停用，不会回退到其他供应商。

本机 `APP_ENV=local` 时，`.env` 中明确填写的 `MIMO_API_KEY` 优先于启动器继承的同名旧变量；生产模式继续优先使用进程注入的配置。其他配置的优先级保持原有规则。修改密钥后需要重启服务。

本项目支持官方普通 API 与中国区 Token Plan 文字通道，配置时校验凭证前缀、端点和模型的对应关系。默认仍用 Pro，不自动更换模型或费用方案。当前语音适配器仅在普通 API 通道启用。模型目录核验于 2026-10-18，不代表账号已获得目录内全部权限。详细配置与真实调用结果见 [MIMO_INTEGRATION.md](MIMO_INTEGRATION.md)。

未填写 API 时，会话、问题、材料仍能保存；通知保存、附件解析、手工整理、确认待办、修改记录、日历导出均可使用。配置模型后可重试之前的问题，继续同一段对话。图片由视觉模型读取，覆盖检查与独立复核也接收同一原图；图片观察明确标注为非逐字引文，重要内容须本人核实。通知整理按每次通知单独确认外部处理；聊天首次发送须授权本次对话，授权可在输入框更多选项中撤回，之后发送会重新确认。取消授权会保留草稿。成功结果仍是草稿，不会自动成为正式待办。

## 从材料开始连续对话

在对话中添加文字、PDF、DOCX、TXT / Markdown、CSV / XLSX、图片或 MP4 / WebM 视频，可以反复补充材料和追问。支持文件夹与 ZIP 导入、完整原件预览、全文检索、版本切换、分支和可撤销分享。每次会话独立保存材料、消息与回答依据；回答时按问题检索当前账号的有效资料、通知原文、待办和日程，并选取相关段落交给模型。不会检索其他账号，旧助手回答不作为事实依据。自填联系方式、学号、工号与登录密码不加入个人条件上下文；用户主动写进提问或材料的个人信息仍可能随相关段落发送到模型服务。

需要办理时选择“转为通知”，仅复制选中的原始材料到通知核对流程。对话回答不会直接变成正式通知或待办；个人课表、简历等参考材料可以不转入。通知保存独立副本，删除对话不同时删除通知副本。

长期记忆仅保存本人确认的条目。通用记忆可跨项目使用，项目记忆只在绑定项目中使用，专题记忆需要在对话中明确选择。可逐条停用、修改、删除，也可关闭某个对话的记忆；本轮明确要求优先。记忆属于本人提供的背景，不能充当学校正式通知。修改或撤销记忆后，后续模型上下文会排除依赖旧版本记忆的助手回答；原消息仍可在页面回看。

记忆可设置生效和失效时间。相同“同类键”表示互斥值：项目规则优先于专题与通用规则，同一最高范围存在不同值时暂不调用，由本人选择保留或修改。对话设置可预览当前保存范围内的候选及排除原因。生成期间相关资料或有效记忆变化时，旧回答会被拦截，核对后按最新内容重试。工程取舍见 [架构决策](docs/ADR-001-execution-and-memory.md)。

长历史会按预算保留近期完整问答和相关用户原句，去重重复约束，保留历史消息时间；不额外调用模型生成摘要，也不改写或删除数据库中的原文。较早内容可能未进入本轮上下文，不能承诺完整回忆所有细节。明确限定资料、仅要文字且材料规模较小的请求，会合并覆盖检查与写作，保留独立事实复核；复杂任务继续完整流程。阶段提示默认来自真实执行状态，不再为改写进度文字额外调用模型。实现与边界见 [上下文、记忆与执行工程](docs/CONTEXT_ENGINEERING.md)。

“我的通知来源”可登记官网、公众号、群与校内平台的名称、用途、学期。QQ 机器人单聊收件和获授权发布账号文章导入已有可配置适配器；凭证为空时显示未配置。接入步骤、权限及验收限制见 [INTEGRATIONS.md](INTEGRATIONS.md)。

## 日常流程

1. **提交材料**：完整正文、附件、来源名称、原文链接及原发布时间。链接只供回查，不会自动抓取网页。
2. **检查解析**：保留原文件；文字按段落或 PDF 页码展示。解析失败、表格或图片缺漏会提示补充与核对。
3. **生成草稿**：调用已配置 AI，或手工增加本人步骤。对照原文检查适用对象、本人期限、所需材料、办理责任与联系方式。
4. **本人确认**：只保存选中的步骤；责任不明、材料不齐和时间不确定的情况需要明确记录核实结果。不要把学院审核时间当成本人提交期限。
5. **办理与跟进**：点击事项填写准备材料、前置步骤、实际提交记录、补件或受理结果及下次跟进时间。完成与取消仍由本人控制，完成不等于学校受理。
6. **处理通知变更**：在原通知记录正式更正、提前／延期、补充、取消或恢复，选择影响的事项与字段，核对前后差异后确认；转述线索保留原安排。
7. **安排日历**：导出 `.ics`，在目标设备导入，并按实际情况记录设备验证。导出之后改期或取消会提示同步；重新导出不等于目标日历已更新。

通知录入、行动草稿、待办编辑、办理记录及变更录入会自动暂存到当前账号。切换页面或刷新可恢复；附件选择在完整刷新后需要重新选择，界面会明确提示。暂存失败时保留本页内容并提供重试和下载入口；出现其他窗口的编辑冲突时不会覆盖新草稿。

误点任务状态后，提示中提供短时间的“撤回”；稍后也可以在“已完成”中恢复。珞珈小信使会在合适的位置陪你整理事项，“个人设置”可关闭轻声问候和小动作。页面尊重系统的减少动效设置。

| 日历 | 明确日期按全天事件，无擅自补 23:59；明确时刻按北京时间换算；稳定事件标识、修改版本、显式提醒时间 |

通知视觉整理每次最多 4 张图片。图片观察不是逐字 OCR 引文；根据图片提取的期限仍要本人核实。2026-10-18 已定位并修复启动进程继承旧密钥造成的 401；正式通知与长历史个性化的真实合成样本调用通过。它们验证主模型链路可用，不代表语音、目标手机提醒或真实学生试点已经验收，具体记录见 [TESTING.md](TESTING.md)。

`NOTICE_INPUT_TOKENS` 默认 65,536，用于通知整理的保守输入预算。文字按 UTF-8 字节数保守计量，图片按官方尺寸规则估算，因此它不是精确分词或实际计费用量；长文即使符合上传字数限制，也可能因段落结构或图片超出该预算。超限时保留全部原件，由本人缩小本次处理范围，或由维护者调整预算后重试。

日历文件是一次导出快照。手机是否导入、是否允许提醒、锁屏后是否通知，需要在目标设备上验证；应用不会伪称已送达。QQ 仅在管理员配置且本人完成一次性绑定后接收主动发给机器人的单聊；公众号接口仅用于获授权发布账号。没有代办学校业务、自动登录校园系统或读取个人微信／QQ 历史的功能。

“日历与提醒”提供 Apple 日历、Google 日历、Outlook 及其他日历的折叠操作指引，并链接相应官方说明。没有文件导入入口的设备可对照待办手动添加日程；首次使用应先创建测试日程，验证时间、通知权限、关闭页面及锁屏后的提醒，再用于重要事项。

当前适合个人本机使用及有管理员维护的小规模部署。提供公开注册不等于已经完成校园规模上线验收。更大范围开放前应根据真实用户数完成容量测试、服务器恢复演练和运行监控。

## 互动回答与附件预览

简单问题保持文字回答。适合计算、计划、对比、数据展示的问题，可由模型组合白名单组件；参数、勾选、排序等交互在浏览器本地完成。默认严格模式先流式显示真实工作阶段，完整回答和互动界面通过引用、组件结构及独立证据复核后才呈现。图片与视频仅允许经宿主授权的资源，模型不能执行任意 HTML / JavaScript / CSS。

默认模型使用自由编排协议：`Section` 组织内容，`Grid` 设置列宽与比例，`Collection` 按记录重复任意子树，`visible` 按条件显示内容。搜索、筛选、排序、聚合与图表可共用同一份数据和状态；按钮可以把所选内容发回会话继续讨论。组件库是原语及可改写示例，并非固定页面菜单。协议仍有节点、深度、数据量和纯表达式预算；不能承诺覆盖所有未来任务，也不执行模型提供的任意代码。

默认 `mimo-v2.6-pro` 开启深度思考，负责确认范围、检索规划、问题覆盖与个人条件分析，以及最终独立复核。Pro 同时根据这些证据自由组织正文和界面对象，原生界面图与状态转换编排也开启思考；已有覆盖结果的纯文字展示关闭思考，温度0.2；Flash 负责短阶段工作摘要。可设置 `MIMO_COMPOSITION_MODEL=mimo-v2.6-flash` 作编排对照，仍须 Pro 核验。模型、思考模式与核验输出预算记入回复记录。最终核验使用 `AI_OUTPUT_TOKENS`（默认32768，包含思考与回答），不再受旧的12000固定值限制；已有程序检查结果传给核验模型，减少重复推导协议。具体缺口最多补查一轮；格式与交互协议最多额外修正3轮，事实语义复核最多额外修正1轮，共不超过5次生成并受整轮时限约束。修正携带未发布草稿和具体诊断，不重复原文检索；事实复核再次失败仍不发布。原句引用、来源 ID、网址和 UI 结构另有程序校验。搜索摘要与已读取网页正文分开标注，保留来源链接、预览和检索时间；用户明确限定只用材料时不联网，明确“只用官网”时不读取私有库。

`mimo-v2.6-flash` 根据实际阶段记录选择少于100字的受约束工作说明，不接收内部推理、回答草稿或材料正文。说明必须属于该阶段的允许措辞，避免捏造主题、工具或完成情况。摘要异步执行、单次最多10秒，失败保留服务器原始阶段说明。处理中可以收起，完成后自动折叠；阶段记录与来源随回答版本保存。停止生成会取消主请求和摘要请求。

本地 `.env` 保存 `MIMO_API_KEY`，已被 Git 忽略。API Base URL 为 `https://api.xiaomimimo.com/v1`；联网需要平台原生搜索权限。启动脚本使用 `--local-env` 显式读取本项目本地配置；常规部署仍遵循环境变量优先。`AI_GROUNDING=true` 为默认值，`MIMO_SUMMARY_MODEL=mimo-v2.6-flash`。严格模式会增加模型调用次数、费用与等待时间；`AI_GROUNDING=false` 仅供开发兼容旧流程，会关闭上述检索和独立核验。

长回复的正文上限统一为 80,000 字符；`AI_OUTPUT_TOKENS` 默认 32,768（包含模型思考和正文），`AI_TIMEOUT_SECONDS` 默认 180 秒控制单次 HTTP 读取等待，`AI_WORKFLOW_TIMEOUT_SECONDS` 默认 1,800 秒控制整轮工作总时长。两者分别限制断流等待和多阶段总耗时，不再用三倍单次超时截断整轮。仍可随时停止或发送补充；补充会停止上一轮，保留上下文后按新要求继续，输入框保持可编辑，未发送的新草稿不会被完成回调清空。

SSE 每15秒发送心跳注释；断开页面订阅不会取消后台核验和保存，重新打开对话可恢复进行状态或完整结果。“停止”和“发送补充”仍会取消对应任务。后台队列有固定容量，断连后不积累未消费的网络数据；进程退出仍会中止任务。复杂长文的 Pro 生成与独立复核可能耗时数分钟。检索计划、覆盖检查和独立核验都允许一次严格的格式修复，来源与事实标准不降低；覆盖检查最多40个需求项。

模型通过 `citation_refs` 选择服务器登记的原文片段，服务器恢复准确引文并检查正文编号、网址与来源的对应关系；独立核验仍检查语义支持。核验器的 JSON 格式错误只允许再核验一次，不能把不支持的结论改为放行。来源入口可展开网页列表，正文引用支持预览与定位，手机使用底部面板。正文、Markdown 表格和裸网址均可点击；代码中的网址保持代码文本。亮色界面使用纯白背景与中性灰文字、边框，保留品牌操作色。

这些检查降低错误风险，不能承诺零幻觉。全文按主题扩展与关键词排序，存在段落预算和隐含语义遗漏；公开正文目前仅自动读取允许的机构域名，其他来源保留搜索摘要。重要期限、资格和手续仍须核对原发布方，网页日期也不自动代表政策生效日期。

附件可以在材料和待办中按需展开：图片和视频使用浏览器原生预览，PDF / DOCX 按提取文字展示，CSV / XLSX 按表格分页展示。文字预览不保留 Office 或 PDF 的原始版式，表格公式不会执行，视频不会自动播放或发送给模型。重要信息应下载原件核对；旧 DOC / XLS 需先转换，扫描 PDF 暂无 OCR。

对话页保留单一顶栏，输入区随内容增高；侧栏可以沿整条分隔线拖动、折叠并重新打开。手机向下阅读时收起顶部和底部导航，上滑或短暂停留恢复。日历月视图、日周时间轴和移动课表按可用高度适配，长列表分页。

可在个人设置选择回答详细程度、风格和偏好，相关条件会传给现有模型调用；学号、联系方式不作为模型个人条件。资料导入只追加并先预览；不会覆盖现有账号数据。原始文件和互动快照不从 JSON 导出包自动恢复。

管理者可将 `.env` 中的 `GENUI_ENABLED=false` 并重启，以恢复文字接口；无需删除数据库或消息。架构、协议、安全及回滚说明在 [docs/genui](docs/genui/DESIGN.md)。

生成式回答按每次问题自由编排内容与交互，默认纯白、无外框，以文字层级和留白组织。
新闻对照、内容简报、公示演练是虚构验收样本，不是限定模型输出的整页模板。
设计原语与交互规则见 [内容编排说明](docs/genui/CONTENT_DESIGN.md)，用户提供的初稿的
逐项采用与拒绝理由见 [方案审查记录](docs/genui/PROPOSAL_REVIEW.md)。

互动回答支持逐项批注和草稿编辑，筛选后保留记录归属、输入焦点与光标；
可以本地撤销、重做、恢复初始选择。直接追问或点击继续分析时会带入经过

## 记忆工作台

“我的记忆”支持长期、经历、会话短期和仅本轮条件；按通用/项目/专题控制范围与跨会话共享。工作记录增量保留目标、决定与进展，支持人工编辑、锁定、晋升、来源历史和 JSON / Markdown 编辑。聊天中的保存状态来自服务器回执，可逐条反馈这次回答的记忆是否适用；过时内容暂停调用，主动遗忘阻止旧历史重新学习。本地整理默认不调用模型，另有默认关闭、授权和预算受控的语义复盘。

使用方法与运维见 [记忆功能升级说明](docs/MEMORY_ENGINE.md)；本轮版本反馈、写入重试、会话修订、复盘可靠性和新管理页见 [可靠性 v4](docs/MEMORY_RELIABILITY_V4.md)；形成、调用、遗忘、反馈与复盘基础路径见 [生命周期 v3](docs/MEMORY_LIFECYCLE_V3.md)；13 个固定提交仓库的技术与落地映射见 [记忆源码审查](docs/MEMORY_SOURCE_REVIEW.md)。最新验收见 [TESTING.md](TESTING.md)，历史轮次保留各自的时间与结果。
